# CombatBrain 2.0 — Charter 与 Roadmap 增量修订建议 v0.2

> 2026-10-21 / 研究分支 / **不覆盖现行上位文档，不变更生产控制权或 P3 合同**。源文件：Charter v0.3（文件名 Charter V0.2.md）、Roadmap v0.2（文件名 v0.1）、Requirements Clarification（2026-10-20）；新增研究稿见同目录 v0.5。

## A. 建议写回 Charter 的产品要求（已确认方向）
| 范围 | 应纳入的原则 | 不要写成的误导承诺 |
|---|---|---|
| 战术 AI | 目标驱动、创造局部优势、条件阶段计划；有限可控试探和浅层敌军反应推演 | 无限博弈树或保证总能预判 |
| 任务语义 | Commander 从有界、可验证、可组合的职责集合下达任务；Formation 在委派约束内自主执行 | 所有任务已经有最终判定阈值 |
| 动态协同 | 跨 Formation 任务依赖、受阻反馈、战机窗口与切换成本 | 固定编组脚本或为求丰富而随机多样 |
| 兵种能力 | 研发期为原版兵种生成静态多维画像；在战斗中聚合 Formation 并使用动态资源、地形、敌我状态 | 战斗时重跑离线画像生成器 |
| 文化 | 能力与战场收益优先，文化为非强制战术倾向 | 文化决定唯一打法 |
| 双战斗模型 | 画像 schema 兼容 Vanilla Combat 与 RBM Combat，分别评估/校准 | 一套数值在所有 RBM 参数下准确 |
| 健壮性 | 未知兵种有基础降级指挥能力；无预生成数据不允许整个 AI 失效 | 首版保证适配所有第三方兵种 Mod |
| 规模 | 纳入 Limitless 大战规模性能与兼容研究，复用统一架构；首版支持以专项验证和成本为条件 | 尚无证据就承诺万人无掉帧 |
| 实施边界 | Agent 战斗行为不改；玩家直接指令优先；原版士气兼容 | 去修改士兵个体逃跑/格挡 |
| 目标 | 敌军增强与 F6 托管首版均需验收，战役野战必须覆盖 | 当前 P3 已有这些能力 |

## B. Roadmap P0—P6 的建议工作包（**映射提议，不代表既有阶段合同已被修改**）
| 阶段 | 增量工作建议 | 可观察证据/完成门槛待确认 |
|---|---|---|
| P0 工程验证 | 兵种数据提取能力、画像 schema 和模型标识、静态加载降级原型、RBM/Vanilla 配置探测实验 | 能重复生成/加载相同数据；断源与版本不符均有清晰回退 |
| P1 最小指挥闭环 | 有界任务契约、分离计划与命令、Formation 实际控制闭环 | 命令确实到达目标 Formation；执行和合规状态区分 |
| P2 空间协作/安全 | 任务依赖、玩家优先级、局部紧急调整与原生控制冲突验证 | 跨 Formation 依赖可重现；不误改玩家队伍 |
| P3 战术实施 | 任务词汇可组合、延续性行为、条件阶段、有限战机利用，逐步结合能力画像 | 策略有效果的独立观测，不只日志声称；**现有 P3 尚未通过，不能据本建议宣布 PASS** |
| P4 对抗自适应 | 局部优势主动创造、有限试探、浅层反应预测、稳定性/滞回、动态任务再分配 | 与基线对照并提供失败场景 |
| P5 泛化和优化 | Vanilla/RBM 不同模型测试、混编/降级、援军、跨文化与战役大样本、性能分析 | 真实战斗证据、缓存命中、CPU/峰值指标及回归 |
| P6 最终验收 | 敌军对玩家、F6 托管、战役野战、必要兼容场景独立验收；玩家体验 | 环境矩阵、盲测/对照、失败和未验证单独披露 |

**风险提醒**：上述阶段对应只是为了方便评审；若原路线图阶段职责与建议不吻合，应回到原版逐项比对，并通过显式变更单调整，禁止暗改既有 Exit Gate。

## C. 对现有开发的影响与禁止事项
- 当前源码/任务登记已经存在，不因为研究分支引入文档就授予 Agent 新的开发任务，也不直接重构 `MissionBehavior`、`Harmony` 接管关系。
- 上位 Charter 的“信息公平”“不刻意犯错”、Formation/Agent 边界继续有效。
- “拥有 10000 士兵”不是“可以自由扫描 10000 Agent 并即时下令”的性能许可。
- 画像预计算不能取代 Formation 动态弹药/生存状态更新；避免错误承诺零运行时成本。
- 不要从 RBM Campaign 装备力量估计推断 CB 野战单位在不同目标前的精确胜率。

## D. 回写前需负责人确认

## E. 建议变更流程
保留现行 `master` 原始资料；研究稿审查通过后单独 PR 提议修订原 Charter、Requirements 与 Roadmap。PR 必须附逐条决策依据、涉及的产品门槛/阶段门影响、尚未确定项清单。提案没有用户最终签收时不得合并为约束性需求。
## F. 新增可观测性/CBATH 研究工作包（2026-10-21）
依据 [CBATH 可观测性升级提案 v0.1](CombatBrain-2.0-Observability-CBATH-Upgrade-Proposal-v0.1.md)，建议后续 Charter 明确“决策—行动—战况—任务反馈—重规划可追溯”，Roadmap 增加单列观测工作包并映射现有 P0—P6 的适用阶段。优先复用现行 ObservationAdapter 的结构化事件与 CBATH 独立观察；补任务进度趋势、重新评估原因和切换依据；待观测协议稳定后再实现可选 Developer Mode HUD。所有功能必须保持决策旁路、按需采集、性能受控，不能修改现行 P3 验收门或承诺所有诊断都在首版发布。现阶段为研究提案，非开发授权。
