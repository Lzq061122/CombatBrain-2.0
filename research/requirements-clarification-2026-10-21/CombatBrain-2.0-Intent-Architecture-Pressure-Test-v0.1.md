## 1. 设计中的根本风险
任务进度、观察窗口、失败尝试记忆、战术价值、全军意图交接和可观测性，若各自拥有修改任务/发令权限，就会形成互相覆盖的决策器。应将它们组织为**每个受控 Team 一条权威决策链**，其余只是事实提供者、候选方案产生器、只读评价器或执行器。

## 2. 意图层级与术语（建议）
- **Victory Objective**：战胜敌军、合理管理损失/风险；玩家直接命令和可控范围为更高优先约束。不是逐 tick 选择的“战术意图”。
- **Operational Intent（Commander，唯一版本化的全军作战意图）**：本阶段希望改变的战场状态（例如“削弱敌方远程支援并建立推进机会”）、理由、首要/必须保障的职责、风险限制与改派/失效条件。描述目标状态，不直接包含原生 Move/Charge。
- **Task Contract（Commander 颁发给 Formation）**：TaskType + Target/Area + Objective + Constraint + AllowedLocalActions + Dependencies + ProgressEvaluator + ExitConditions + Authority + Version。不同任务可合作实现一个 Intent；不能用“已发令”等价“达成战术效果”。
- **Local Execution Choice（Formation 局部执行选择）**：例如“从右翼绕行并保持楔形”“暂时停止冲击重组”，是满足任务契约的行动方案；不能再设计一个与 Commander 同级的全军意图生成器。Formation 可报告 CandidateOpportunity/Blocked/AtRisk，请求 Commander 改派，但不得私自改写 Task Contract 的目标。
- **Engine Order**：最终被有权入口合法写入原生引擎的指令，由现行 Arbitration/Execution 控制链处理。

## 3. 意图从何产生（PROPOSED）

```text
FormationSnapshot + 兵种能力画像 + 任务/计划历史 + 原生授权状态
                      |
                 BattleFacts
                 (带时间与置信度)
                      |
            SituationAssessment
           (威胁、机会、风险、可行性)
                      |
          CandidateIntentGeneration
       (有限目标类型 + 参数化目标/空间/职责)
                      |
            Feasibility & Constraints
                      |
          GlobalValueComparison + Stability
                      |
         Commander OperationalIntent vN
                      |
           TaskAllocator / Dependencies
                      |
           Formation TaskContract vN
                      |
             Formation Local Policy
    (选路、列阵、接敌、重组、局部脱离)
                      |
                ActionProposal
                      |
         ProposalArbiter / ExecutionGate
                      |
                Native Formation Order
                      |
               任务反馈/实战结果
                 [下一次评估]
```

**Commander 的候选意图来源**不是凭空“思考”，而是由相同时间基准的事实 + 兵种相克/地形/任务能力 + 威胁机会评估，生成有限类型的参数化目标，先检验执行约束、队伍能力及交接成本，再按已批准的分层价值评价挑选或维持当前意图。全军意图候选例子：降低敌方有效远程压力、建立中央可利用突破、保护己方弓兵、切断敌方某一路调动。**不是**固定文化脚本，也不是对一切可能战术做无界搜索。

**Formation 的候选执行方式**来源：已签收任务的目标/约束 + 自身能力 + 附近敌我 Formation 状态 + 地形、队形、疲劳/受损/弹药等实际可得数据 + 短期失败尝试记录。选择“下一步怎么做”，不选“整场战役应该追求什么”。遇到不可解决的冲突，提交状态/机会报告，由 Commander 重新分配任务；紧急局部脱险的边界须单独批准。

## 4. 一个可检验的完整例子（PROPOSED）
- Fact：敌方弓兵有效火力强，我军中央遭持续压力，右翼骑兵数量/装备适于机动，敌右翼有步兵拦截；事实的观测来源、时刻和不确定度都可记录。
- Commander 生成“降低敌军弓兵威胁”等若干候选全军意图；检验行动可行性和全局价值。若采用此意图，则派任务：步兵牵制、弓兵压制、骑兵寻找后排攻击窗口、必要侧翼保护。
- 骑兵 Formation 发现右翼路径受阻，自行尝试契约内允许的重新选路/临时重组，并上报 TaskProgress+Obstruction。不得自行把“袭击敌弓兵”改成“消耗敌步兵”。
- Commander 接收到可靠的停滞/代价/新机会证据，比较当前意图与“通过中央消耗再突破”等全军候选；若新意图全局明显更优，先完成关键保护任务的继承/转交，再原子发布新 TaskContract 版本。旧任务不能再次发令。
- CBATH 只能记录/验证事件，不能向决策器回注“日志描述”作为事实。

## 6. 防止“屎山”的七项约束（PROPOSED）
1. **唯一写令入口**：每个 Formation 每个控制域由现有裁决/执行门做最终合法写入；计划器和任务监测器禁止直接改游戏 Order。
2. **单向依赖**：战场事实只读 → 候选/评分纯函数 → 版本化意图/任务 → 局部执行 → 合法写令。反馈只进入下一次状态评估，不允许跨模块回调修改上游对象。
3. **一份事实版本**：同轮比较所有候选使用同一已知时间基准的 snapshot；过期/缺失不当作零值。
4. **一套任务生命周期**：不要为“失败重试”“任务交接”“CBATH 回放”创建几套互相竞争的状态机；任务完成、受阻、取消、违约与预测不确定分别表示。
5. **显式版本交接**：意图/任务 revision 改变时，旧版本候选不得落地；关键防护职责继承或明确承担风险，避免交接瞬间出现防线空档。
6. **算法与观测分离**：日志/HUD 只读，默认零昂贵诊断，不能依赖日志系统驱动战术；不进行每帧逐 Agent 深度扫描。
7. **最小纵切片先行**：先用一套“牵制步兵 + 侧击骑兵 + 掩护编队”从意图生成到反馈/重评/交接验证闭环，然后再增加候选意图、任务类型和 RBM/Vanilla 画像；避免预先建立通用多智能体平台。

## 7. 可自动化架构测试（PROPOSED）
- 同一 snapshot + 同一战斗历史/随机种子 → 候选和已批准决策可重复；运行顺序不同不应修改安全权限。
- 单个任务换目标不应隐式改变 Operational Intent；Formation 没权限直接撤销其他 Formation 任务。
- 同一 Formation 不能同时收到两个并行写令；玩家手动接管阻断后续过期提案。
- 任务 revision 更换后旧订单必须被拦截；仍需保留的防护职责有明确承接者或经过 Commander 同意接受风险。
- 任务失败与抗命独立；进展未知不能被记成“完成”。
- CBATH/HUD 启用与否不能改变决策语义；性能预算和内存分配应在原版及极端人数条件实测。

### 9.1 信息视野（复核现行 Charter §14，而非新增限制）
**REAFFIRMED**：默认可读取全战场已部署敌我兵力、编队位置与队形、兵种装备/能力、作战状态和地形等可供指挥视角获得的信息；不造人为迷雾、可见性噪声、侦察开锁或技能驱动的视野缺损。旧版 `KnowledgeView`（置信衰减/噪声）和 `VisibilityOracle`（遮挡迷雾）已在 `Agent/r4-asset-audit.md` 按 Charter §14 标为 REJECT，不应复活。
**边界仍有效**：不读取玩家未执行指令、私有意图、未来随机结果和未入场增援的无依据未来状态；“API 能读”并不自动等于有资格用。观测延迟/缺失和战术预测不确定性属于技术事实，不应伪造成迷雾。Terrain LOS/坡度/遮蔽可以影响真实交战效果与路径可行性，但不等于 AI 必须假装不知道敌军部署。

### 9.2 三个不同语义（候选定义，PROPOSED）
- **Threat（威胁）**：特定敌方力量、地形/态势变化，对我方特定重要单位/职责，在可评估时间窗口内具备显著不利影响的条件。记录 Source, Victim, Mechanism, TimeToImpact, Severity, Confidence。
- **Vulnerability（弱点）**：敌方或其部署/任务依赖相对我军某项可用能力的可利用缺口；不等于“兵种少”“数值低”。记录 EnemyObject/Region, WeakRelation, ExploitingCapability, ValidityConditions。
- **Opportunity（战术机会）**：特定我方 Formation（或协同集合）能在有效窗口内利用可达弱点/威胁转移，预期对当前全军意图或胜利目标产生超出代价的净效益的*可执行候选*。记录 Actor, Target, DesiredStateChange, FeasibleActionFamily, Prerequisites, ETA, Window, Impact, Risk, Confidence, Evidence。
- 三者不能合并成一个含糊 “EnemyWeakScore”；观察事实、能力匹配判断和未来效益预测各自标注来源。

### 9.3 发现流程（PROPOSED）
1. **Fact ingestion**：同一时间基准读取部署中的各 Formation 及成员构成的聚合快照；读取预生成能力画像、低频地形/通行缓存、命令/玩家控制权限。避免每帧遍历每个 Agent，未知数据标 UNKNOWN。
2. **Relations / situation features**：建立双方有空间关联的 Formation 与区域之间的关系：接敌/接近时间、射程覆盖、距离与通路、队形朝向及侧后暴露、相对机动、局部能力匹配、局部支援与威胁重叠、人数/弹药/士气动态变化、地形阻塞、依赖持续性。不要只看人数比例。
3. **Threat/Vulnerability detectors**：使用小规模、可解释的特征规则/连续阈值和事件变化识别候选异常。例如敌骑 ETA 小于我弓兵重新布防时间→防护威胁；敌弓兵近战支援被友军牵制且我骑兵能及时到达→候选弱点。
4. **Opportunity instantiation**：以“目标状态变化 × 有关目标对象/区域 × 可承担角色的己方编队”生成有界候选；以基本权限、地形、ETA 和能力条件剪枝；不先枚举所有完整战术剧本。
5. **Intent evaluation**：在候选少量化后，逐项检查任务分配、协同依赖、预计收益/风险/切换成本/不确定性，和当前 Intent 比较；无法实际行动的不叫可用 Opportunity。
6. **Feedback/reassessment**：观察任务实施前后事实、是否达成进展/是否出现逆转、是否有新条件使先前无效机会恢复；所有推断可旁路输出 CBATH，但 CBATH 不成为输入事实源。

### 9.4 第一批机会检测类型候选（不是已批准的目标/任务库）
| 检测模式 | 证据 | 可生成的状态目标 |
|---|---|---|
| 关键己军受远程压制 | 射程/距离/火力威胁与己军损失变化 | 降低远程威胁 |
| 侧后方近战掩护不足 | 目标暴露、保护编队位置、实际可达性与 ETA | 削弱特定敌军火力/侧击 |
| 局部战线力量不匹配 | 局部参与兵力及武器匹配、到达时间 | 集中局部优势或避免被突破 |
| 阵线裂口/关键阻挡减少 | 敌编队分离、受损、阻挡区变化、我方可利用路线 | 建立/扩大战场通路 |
| 敌方关键编队被牵制或调离 | 敌支援编队位置/当前实际交战、反应 ETA | 趁机机动、压制孤立目标 |
| 地形适配差异 | 高地/隘口/树林/可通行宽度及兵种适性 | 占据有利位置或诱敌进入不利地形 |
| 资源/承受能力下降 | 可用弹药、剩余有效编队人数、士气征兆（可读则用） | 消耗、撤出、抓住短时弱点 |
| 友军关键角色失去保障 | 掩护关系破裂、敌翼机动威胁、救援 ETA | 恢复防护或有序脱离 |

### 9.5 明确的反例
- 敌弓兵数量较少 ≠ 可以直接骑兵冲锋：如果有枪兵掩护且路径不可达，不形成可执行 Opportunity。
- 高地 ≠ 自动占据：若弓兵射界被遮挡、移动时间过长或造成侧翼暴露，可能净收益为负。
- 攻击受阻 ≠ 永久不可行：敌枪兵被调离或受损后可重新评估；无新证据时避免重复相同冲击。
- 全地图可观察 ≠ 预测正确：敌方未来会不会回援仍需基于可观察变化估计，不读取隐藏 AI 意图。
- 侦测到局部好机会 ≠ 立即修改全军意图：仍须 Commander 检查当前目标、风险和职责交接。

### 9.6 工程边界
当前 `Program/src/Core/BattleState.cs` 明确主要是同批编队中心、人数、远程/步兵数、RangedEdge、StrengthRatio；`BattleAssessment.Read` 使用有限的双方 Team 归属规则。现有信息不能被误称为已能评估交战射界/侧翼通路/协同 ETA。新关系特征应从统一 Fact/Capability 层扩展，以可测试的纯函数为优先；阶段性代码和 P3 参数不得自行覆盖。战场空间可优先采用编队/有限地形节点稀疏邻接关系与缓存，而不是万人 Agent 两两配对或每次全图高分辨率热力图。真实 CPU 开销需原版、RBM Combat、Limitless 场景分别验证。

## 10. D-OPP-01 已确认：统一关系分析 + 有限可组合检测器（2026-10-22）
**CONFIRMED，用户选择 B**：统一 Formation/区域级战场关系特征是机会发现的数据基础；使用**有限可组合**的 Threat/Vulnerability/Opportunity 检测器，而非各战术自建一套互相冲突的事实模型，也不以完整预设战术为唯一来源。预制战术可以作为执行经验/先验，不构成硬绑定。此决定仅批准架构方向，不批准具体检测器数量、算法阈值、更新周期或 CPU 预算。

推荐分层：同一时间基准的战场事实和离线能力画像 → 按空间、任务、潜在接敌筛选相关 Formation/区域关系 → 计算威胁、克制、有效掩护、ETA、射界、地形、支援、任务依赖等可测关系 → 有界检测器组合识别弱点与潜在机会 → 按权限、可达性、窗口、协同与风险分阶段筛查 → Commander 与既有 Intent 做全局比较。事实、预测、决策及执行结果分离。

**主动创造机会**：通过任务协调和有限试探尝试改变敌方掩护/牵制关系；假设敌方会被引诱、回援或转向只可作为带不确定性的预测。未观察到关键前提成立时不能把机会视为兑现。Formation 不因此取得独立修改全军目标的权限。

**反失控约束**：稀疏相关关系优先，避免 Agent 两两计算；昂贵评估仅对少量通过初筛的候选进行；对失效/重新出现的机会保留反馈，避免无新证据反复重试。机会出现不自动发令，需遵循意图稳定性、切换成本、任务版本和玩家控制仲裁。

**仍 OPEN**：首版关系维度及语义、具体检测器集合、观测来源与缺失处理、置信度/误差、可用性与窗口阈值、候选上限/预算、不同战斗模型的校准与实机验证。

## 11. 下一待裁决：D-EVAL-01 战术价值评估
Commander 如何比较不同可执行候选对**最终获胜**的边际贡献？何时可以为了赢得战斗牺牲局部编队，何时因为风险、资源、时机、协同任务、换令成本而维持当前 Intent？需区分硬安全/指挥权约束和可权衡的战术代价，并避免宣称未经校准的“精确胜率”。
