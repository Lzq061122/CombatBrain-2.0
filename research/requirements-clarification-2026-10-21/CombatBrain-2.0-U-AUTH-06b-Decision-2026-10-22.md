# CombatBrain 2.0｜U-AUTH-06b 明示牺牲性命令与极端生存例外优先级（2026-10-22）

> **CONFIRMED（产品/权限原则）：U-AUTH-06b 方案 C**。`LossOfDutyCapability` 的可观测指标、置信/持续窗口、紧急例外的时限和局部动作、任务健康报告字段均属 **OPEN/PROPOSED**；本次纸面反例检查**不是实机 PASS**。仅研究分支，不修改 `master`、现行 P3 合同、CBATH 或生产代码。

## 1. 用户明确选择与最终签收

用户于 2026-10-22 在 U-AUTH-06b 备选 A/B/C 后回复“**C**”。

**CONFIRMED｜Commander 的明示牺牲性关键职责原则上优先，但 Formation 已实质丧失原定履职能力时，才允许与 U-AUTH-06 相容的、最小必要的局部紧急例外。**

1. **允许有意识的必要牺牲**：Commander 可以在全军胜利优先的前提下，明确承担某 Formation 的重大伤亡并要求持续牵制、护卫、守备等职责。Formation 不得只因自己的伤亡高、预计损失大、任务推进困难或局部收益为负，就以“求生”之名解除该职责。
2. **“无法履职”与“高危险”是两项不同条件**：越过该类明示牺牲职责时，必须有**该职责已经不能产生实质预期效果**的可观察证据，并符合 U-AUTH-06 的迫近、严重且在普通安全包络中无法化解的危险。单一人数百分比、低士气信号、预测高伤亡或局部 `BLOCKED` 不能自动判定职责已无效。
3. **紧急例外限于最小范围**：即使条件成立，也只允许已拥有合法 CB 写令资格的 Formation 采取现实可行的最低限度防御、短程脱离、重整等必要动作，立即报告 Commander；禁止全军撤退、越过玩家命令、改变其他 Formation 的任务或自行更改全局 Intent。无安全可行动作时，不可虚构可安全撤退。
4. **不要制造假的全知失能证明**：实际引擎观测有限，不能承诺计算“客观不可能”或零误判。对证据不足的预测危险，应报告 `AT_RISK/UNKNOWN`、执行当前仍可行的合同动作，并请求 Commander 重新评价，而不是把不确定提升为已证明丧失履职。具体证据和时序约束保留为 OPEN。
5. **原生个人溃逃独立**：Formation 的纪律/合同只能约束 CB Formation 层，不能强制每个原版 Agent 不逃跑。若 Agent 自然溃散导致职责实质无法执行，应如实更新有效能力与责任失效状态，不改 Agent 士气/行为。
6. **职责尚有效则仍受 C17 约束**：牵制目标仍有效但进攻手段失败时，Formation 可以在 U-AUTH-05 包络内改防御/阵型或暂时离开危险接战点，**不因突破失败就允许放弃有效牵制责任**；职责解除/承接由 Commander 判断，除已满足上述极端例外外。
7. **权限与版本更高优先**：玩家手动/F6 收回、不同 Legal Command Domain、CB 关闭、身份 epoch/Task Revision 变更应在实际写令处阻止 CB 旧紧急命令；越过 Task 安全包络不等于越过原生控制权。

## 2. 反例压力测试（纸面逻辑，不是游戏实测）

| UA06b-4 | 兵力很少但守在唯一狭窄门口，仍能迫使敌方调动 | 不能仅凭人数少或预估战损即认定已失去守备效果 |

| UA06b-9 | Agent 原生个体溃逃导致编队不能形成战线 | 尊重 Agent 原生逃跑，Formation 层按有效组织能力报告损失与职责失效，不声称 CB 控制 Agent |
| UA06b-10 | 威胁估计在阈值附近振荡、不断切换坚守与自保 | 报告、应急持续性、失败记忆和恢复版本均需防抖；阈值时序待验收 |

**结论**：方案 C 与 P09 胜利优先、C17 关键职责连续、U-AUTH-04 B、U-AUTH-05 C、U-AUTH-06 C、D-ARCH-01、D-EVAL-01、P05/P06 和 U-SIDE-01 原则一致。其脆弱点是把“不可能履职”过于简单地绑定伤亡百分比、任务进度或模拟预测，这些不能升格为已确认判据。
