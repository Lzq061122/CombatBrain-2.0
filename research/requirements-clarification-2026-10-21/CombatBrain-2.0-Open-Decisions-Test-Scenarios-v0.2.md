## 2. 最小场景模板（每一项需记录环境、构建、随机种子/配置、初态、实况、终态）
### TS01 牵制与违令分离
步兵任务是迟滞中央敌军；在目标时间段中受损被迫后撤。分别验证任务 FAILED、CONSTRAINT_BREACH 和不可判定时的 UNKNOWN，不把被推退直接判为违抗 Commander。

### TS02 局部战机与全局约束
弓兵暴露且敌骑回防，执行掩护任务的骑兵看见短时攻击机会；若攻击会破坏核心掩护，应保持职责并汇报请求，不应自顾冲锋。

### TS03 跨 Formation 协作取消
步兵牵制崩溃，侧翼骑兵预计 20 秒后才到达敌后方；原依赖失效，应评估取消/改派而不是继续冲锋。20 秒是输入情境，不是项目固定重规划阈值。

### TS04 试探与反应预测
有限兵力向前试探，观察敌军变阵再决定是否实施主攻；测量是否采集到反应、是否不必要地重复试探，以及是否在信息不足时承认不确定。

### TS05 多文化弓兵
将不同装备的弓手或弩兵分别编入 Formation，相同敌人和地形下评价其射程、持续火力、防护与交战位置差异；更换敌方盾牌/骑兵后查看任务选择是否合理变化。测试目的不是“文化必须打得不同”。

### TS06 混编未知画像
150 已知兵种 + 50 未知兵种；未知部队缺装备字段也不能全队零强度、空指针或使 Commander 停摆。只需稳定基础职责，不宣称完整第三方兵种兼容。人数为示例而非固定要求。

### TS07 双战斗模型差异
相同兵种与目标分别在 Vanilla Combat、RBM Combat 默认配置测试；比较预计算画像与真实结算是否基本一致；修改 RBM 核心参数后验证告警或保守降级策略。误差门槛 OPEN。

### TS08 原版士气与 Agent 不干预
当局部编队开始溃散，Commander 能发现可用兵力下降并调整可控 Formation 的任务；不阻止个体 Agent 按原版规则逃跑，也不宣称取消原版全军溃逃。

### TS09 玩家 F6 与直接命令
玩家委托 F6，AI 可合理控制授权编队；玩家重新向某编队下达直接命令后，AI 不得抢夺控制；非玩家敌军测试与玩家 F6 必须分别记录结果。

### TS10 增援、多领主、多 Team
引入不同阵营 Team 或援军先后入场；检查观察与权限归属是否准确。仅有 `FormationSampler` 遍历各 Team 不构成验收通过。

### TS11 Limitless 大规模
在可用场景中逐步提升实际同时活动的士兵数量，记录 Formation 数、CPU AI 毫秒、尾延迟、内存、命令抖动、导航与多 Mod 冲突；如果不能实际达到上万活动士兵，明确记录未验证而非推断通过。

### TS12 低频计划/高频局部机制
战机稍纵即逝与持续有效两组输入；评估“发出任务前就失效”以及“重规划导致往复横跳”。验证窗口、切换成本、紧急例外与稳定性的平衡。

## 3. 证据记录格式
每个场景至少记录：测试 ID、战斗模型、版本及配置、构建/commit、有效样本数、原版/RBM 对照版本、初始编队与任务、输入事件、Commander 决策、Formation 实际命令、独立观测结果、状态评价、资源成本、异常、是否复现、最终判定（PASS/FAIL/UNKNOWN）。
**必须把日志陈述与实际观察分开**；不能只以“AI 打算牵制”证明敌人被牵制。

## 4. 澄清工作结束的门槛
首版范围与 U01—U10 关键裁决都有负责人签收；测试矩阵与可测验收口径已明确；Charter/Requirements/Roadmap 的术语、边界和阶段约束一致；当前 P3 合同及历史 Exit Gate 的事实地位得到保留；没有隐式变更用户已作出的产品选择。

## 5. 下一场讨论建议
优先针对 U01：确定首版最小、但足以体现协同的战术职责集合；逐类写清 Goal、Constraint、LocalFreedom、Dependency、ObservableEvaluator，再决定是否应拆出新类型。不要直接把上文所有候选任务视为已批准。
## 6. U11：CBATH / RBM AI Log 启发的观测功能（新增，未签收）
- **已确认（2026-10-21）**：采用 A，CBATH 日志与离线回放/分析优先，Developer Mode 实时 HUD 后置；不能把观测层变成指挥决策的必需依赖。性能与故障隔离为必要验收条件；当前 P3 合同不变。
- **仍待决**：是否将结构化决策溯源、任务观察窗口、失败尝试与重规划比较统一为旁路事件 schema；游戏内 Developer HUD 是否首版必需；CBATH 深度独立观测/离线时间线工作量与现有观察组职责如何协调。详见 [升级提案](CombatBrain-2.0-Observability-CBATH-Upgrade-Proposal-v0.1.md)。
- **TS13 周期快照/即时事件对齐**：短于采样间隔的多次战术/命令切换仍有事件；快照可复原变化前后的真实状态；事件具战斗、编队、任务和时间身份。
- **TS14 意图与结果分离**：CB2 称任务已完成但独立 CBATH 未见实际目标变化时，不得报告 PASS；区分自主调整与玩家接管造成的写令结果。
- **TS15 开销与故障隔离**：关闭/开启 Developer Mode、SUMMARY、DETAILED、CBATH-SESSION 模式分别测量 AI 毫秒和帧时，并检查决策不变性；日志目录不可写、队列满、时间对齐错误均不得造成游戏崩溃或指挥停摆。
- **TS16 人数规模**：实际高人数场景中禁止默认高频逐 Agent 槽位采样；确认受限诊断或关闭深度采样后表现符合待确定的性能预算。

## 7. U01.5 确认与 U01.6 待裁决（2026-10-21）
**已确认**：选方案 B，Commander 维护显式、可调整的全军 Operational Intent，并将其分解为互相协调的 Formation 任务；局部执行与任务改派不能随意背离全军当前战术方向。该决定不授权开发 Agent 变更既有 P3 接管路径。
**待决定 U01.6**：何时可升格为全军作战意图变更，而不只是调整局部任务；硬失效是否优先打断、可行替代意图的比较是否考虑协同成本/撤换风险/已投入资源，以及改变主攻前如何保持牵制、侧翼保护等关键任务的连续性。
**TS17 候选：局部利好但全局不利**——右翼骑兵持续消耗敌方步兵，但敌后弓兵仍严重威胁我军；验证 Commander 不因局部击杀自动放弃全军消除远程威胁的意图。
**TS18 候选：全局威胁重排**——远程威胁已明显受抑、敌中央形成可利用缺口；验证 Commander 能重新评价意图并协调多个 Formation，且不会因瞬时信息摆动产生主攻横跳。
**TS19 候选：过渡交接**——需要把侧翼掩护骑兵转为突破任务；验证旧责任被明确接替或经 Commander 评估允许暂时空缺，而非所有编队同时清空旧任务。

## 8. D-ARCH-02 决策与机会发现验证（2026-10-22）
已确认采用**状态目标驱动**而非完整战术模板匹配；现行 Charter §14 的全战场观察原则重申，不增加人为迷雾/可见性闸。D-OPP-01 已确认采用统一关系特征与有限可组合检测器；具体特征、阈值、置信度、预算和效果校准仍 OPEN。
- **TS20 完整信息但不可偷看未来**：战场已有单位位置、编队/兵种/地形供 Commander 观察；但玩家未执行指令和未出现援军的未来状态不得作为已知事实。
- **TS21 敌后弓兵被掩护**：敌方远程单位表面暴露，但长枪兵有效阻挡路线；若骑兵无法在窗口内进入，不得判为可执行侧击机会。
- **TS22 窗口形成/关闭**：敌掩护步兵被牵制后出现新通路，Commander 发现机会；恢复掩护后需及时下调可行性，不重复尝试同一受阻路线。
- **TS23 地形利弊**：高地可见但射界、路程、坡度或翼侧风险导致净收益为负；不以“高地=必占据”硬编码。
- **TS24 规模控制**：人数增长但 Formation 数近似不变时，关系/机会评估开销不得随 Agent 数平方膨胀；MCM/CBATH 日志关掉仍能正确生成候选。
- **TS25 局部与全局分离**：检测到敌编队可消耗的局部优势，但原 Intent 的主要威胁仍在；不能因为局部高分未核对职责交接就改变全军方向。

## 9. D-OPP-01 机会发现架构已确认，D-EVAL-01 待决（2026-10-22）
**CONFIRMED**：项目负责人选 B——统一的 Formation/区域级稀疏战场关系特征 + 可组合的有限 Threat/Vulnerability/Opportunity 检测器；以预制完整战术脚本作为可选执行经验而非唯一发现机制。必须先筛选有关对象，再分级检查权限、可达性、ETA、时间窗口、兵种对抗能力和协同前提；发现局部机会不能自行切换全军作战意图。Commander 可有界地通过牵制/施压尝试创造机会，但预测敌方反应不能等同已观测事实。

**TS26 同一事实多种解释**：敌后弓兵受到保护、我方骑兵具备机动优势；关系层应同时表达“弓兵可受近战威胁”和“当前有效掩护阻止接敌”，检测器不得未经可达性检验就宣称可执行 Opportunity。

**TS27 跨场景组合与解释**：分别通过敌方枪兵主动移动、被我步兵牵制两种不同原因使掩护关系弱化，使用相同关系特征/检测器产生可能机会；记录构成机会的证据链，避免为每一个完整战术剧本手工复制判断。

**TS28 创造机会不等于预测成功**：Commander 发起正面施压希望诱使掩护部队离开，设置敌军无反应、部分反应、反向增援三组回放；不可把假设反应当成已经发生，未达成条件时不得机械启动骑兵侧击。

**TS29 稳定性与规模**：战场局部机会短暂出现/消失、Formation 数近似固定而 Agent 总数增长时，确认不会因此触发无界枚举或逐 Agent 两两扫描，也不因局部评分抖动无批准地反复改派；独立记录模型、构建、帧时和 AI CPU 指标，阈值待签收。

**下一问 D-EVAL-01（OPEN）**：对可执行战术候选如何做全局价值比较——胜利导向、伤亡/风险、计划稳定性、协同代价和预测不确定性的关系与评价口径。以上测试为设计候选，不等于实现或 PASS。

| TS36 | 敌方增援入场且改变战术力量平衡 | 实际入场后合法归属、任务版本/重新评估与编队整合，不假设未入场援军已经可调度 |
| TS37 | 已知兵种和缺画像第三方兵种混编，轮换 Vanilla/RBM Combat | 未知不可零化、动态弹药/生存状态覆盖、模型版本匹配；专项画像不是先决 |
| TS38 | 同时开启 RBM AI 和 CB 指挥层 | 检测/说明写令冲突，要求或引导关闭 RBM AI/安全不接管；不假称深度共存 |
| TS39 | 大规模载荷导致额外候选/预测计算超预算 | 按顺序降额外计算，但玩家权限、关键 Formation 职责、基本反馈和安全退出仍真实可用 |
| TS40 | 守护弓兵的骑兵附近出现短暂击杀机会；主战线风险仍在 | Formation 不越权改变任务；Commander 才能确认合法替代与交接 |
| TS41 | Commander 期待牵制敌枪兵，为骑兵创造突破，但敌枪兵始终不动 | 不把预测当实际，机会不能直接兑现，停止无证据的重复冲锋 |
| TS42 | 正常原版士气导致局部溃退 | Commander 重新评估可用 Formation；不承诺修改个体 Agent 溃逃 |
| TS43 | CB 战术日志判定“已完成”，CBATH 独立观测没有相关战场变化 | 分别保留动作、任务、效果与整场结果，不得用日志自证成功 |

- **RBM 兼容选 A**：RBM Combat 优先，RBM AI 深度同启不作为首版门槛；未知兵种需基础降级，其他兵种专项 Mod 适配后置。
- **C19 计算预算降级已确认**；定量预算仍 OPEN。
