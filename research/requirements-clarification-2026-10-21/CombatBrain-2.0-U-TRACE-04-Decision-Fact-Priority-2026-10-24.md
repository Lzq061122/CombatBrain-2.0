# CombatBrain 2.0｜U-TRACE-04 降级时的关键事实优先保留原则与纸面压力测试

日期：2026-10-24｜**原则 CONFIRMED；具体最小事件、降级机制、指标及实机 OPEN**

## 一、裁决来源

在 U-TRACE-03 方案 C“日志故障不得阻塞 Commander，诊断允许有界降级，证据不完整不能伪装完整”确认后，助手提出 U-TRACE-04：日志降级时优先保留什么？

- A 均匀保留各类事件；
- B 只保留最终计划与命令；
- C（推荐）**优先保留关键决策事实与追踪完整性信息，优先削减高成本候选细节**。

助手最后明确询问“是否按关键决策事实优先、高成本候选明细次之的原则组织开发者日志降级？”用户明确答复：**“是”**。

故确认 **U-TRACE-04 方案 C 的优先级原则**。这是诊断预算内的相对优先次序，不是所有关键事件必定无损落盘的承诺，不包含固定的字段表、优先级编码、限额或日志系统实现授权。

## 二、CONFIRMED｜原则语义及继承的边界

1. **关键决策事实优先**：在日志容量/处理预算受限时，优先尝试保留能回答“什么条件/事实触发了检查、当时实际采用哪一有效计划或处理、哪些主要权限/职责/任务条件/预算限制导致选择或维持、是否停止/截断、可确认的记录范围如何”的信息；高成本候选详细参数/完整搜索轨迹/逐 tick 中间计算次之。
2. **因果归因价值优先于日志数量**：即使保留了大量低价值候选中间值，如果缺失决策身份、结果和范围，依然不能声称恢复了完整推理。具体何谓“最低事实集”和量化排序还没有选定。
3. **优先级并非无损承诺**：受控降级时优先尝试保留关键事实；如果磁盘断电、通道崩溃、进程异常或内存严重不足，仍可失去一部分甚至全部记录。是否完整必须由证据证明，不能因“最高优先级”字样默认完整。
4. **不能牺牲实时战斗控制**：继承 U-TRACE-03/C19/AR-13 的实时 Commander、F6/玩家权限、关键职责和故障交还优先。不得为了关键记录阻塞主线程、强迫生成更多候选、改变候选排序/运行时决策。
5. **内部记录与外部独立观测严格分离**：较高优先级的内部“已选择/已发送”事件不等于 Formation 真实执行、真正牵制敌军或全局收益。仍依 IF-DATA-03A/CB-014/CBATH 关联核实，证据不充分保留 UNKNOWN。
6. **日志覆盖和阶段含义保持真实**：应区别关键事实已记录、仅部分覆盖、事件丢失或整个窗口不可确认；不允许用摘要伪造未计算的候选评分和未执行的评估步骤。实际完整性证明与格式仍 OPEN。

## 三、纸面反例与必须避免的误解（非自动化、非游戏实测）

| ID | 反例 | 原则性判定 |
|---|---|---|
| TR04-01 | 仅保留最终方案，却丢失触发条件和重要约束 | 不足以支持“为何选择”的归因；关键事实不等于只有结论 |
| TR04-02 | 候选明细完整，但没有决策身份/当前计划/结束状态 | 低归因价值，不能以总行数证明完整 |
| TR04-03 | 日志降级后写入“所有候选已比较”，实则预算截断 | 不能以优先级摘要填补实际未发生的计算 |
| TR04-04 | 存储故障，关键结论也未落盘，却宣称高优先级因此必可恢复 | 保留优先 != 持久化保证；证据不足应 UNKNOWN |
| TR04-05 | 为保存最小摘要，Commander 等待主线程同步 Flush | 与实时控制优先相冲突，不允许 |
| TR04-06 | 只留“plan.selected”，事后将其当作真实执行成功 | 内部决策与独立观察事实分离 |
| TR04-07 | 玩家接管后保留上轮候选为“当前有效安排” | 必须按时间和授权上下文解释，不能由旧记录覆盖当前权限 |
| TR04-08 | 日志在战斗中段开启，却输出整场汇总为完整记录 | 仅能够覆盖实际开启/成功录制的区间 |
| TR04-09 | 为减少日志丢失关闭部分 AI 必要反馈 | 日志不得改变 AI 决策循环、最低控制保障 |
| TR04-10 | 通过额外计算生成一段漂亮的自然语言“原因” | 只能忠实呈现真实计算依据，不能事后杜撰理由 |

**纸面结论**：方案 C 与 U-TRACE-01/02/03、D-DATA-03/IF-DATA-03A、C19/AR-13 原则兼容；这些反例没有经过实机验证或性能测量，不等于实现/测试 PASS。

## 四、继续 OPEN

- “关键决策事实”的最小实际字段、具体事件名单、优先级和保留顺序。
- 重要决策触发条件、抽样与继续当前计划的界定；何时有必要保留候选概要。
- 事件完整性/丢失信号的可靠性、证据水位与格式，尤其是磁盘完全不可写时的状态。
- 模式开关和默认策略、压缩/聚合、缓冲容量、异步 I/O、采样/存储轮转和回放工具。
- CPU/内存/IO 预算、日志开启关闭带来的控制时序扰动及独立实机验收。
- 与现有 ObservationAdapter/Cb2Log、CBATH 的具体工程接口，**不批准直接迁移/改写代码**。

**下一步建议**：U-TRACE 的需求方向、追踪深度、缺失证据语义、故障降级及保留优先级均已形成原则闭环；可暂停日志子专题，按更高价值的核心战术架构未决项（如 AR-04/05/06）继续。若后续进入 U-TRACE 实施设计，再细化具体 Schema、字段和验收，不需要现在因每个工程字段反复询问用户。
