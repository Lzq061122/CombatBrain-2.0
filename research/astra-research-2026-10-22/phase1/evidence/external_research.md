# CB2 外部技术研究与机制选型证据

研究日期：2026-10-22（Asia/Shanghai）。范围：Formation 层候选产生、联合分配、时间协同、有限敌方反应、保持/切换与有限主动行动。所有 CB2 采用判断均为设计推论，未在 Bannerlord 中实测。本记录不把其他游戏的胜率或耗时转移为 CB2 证据。

## 1. 会改变选型的结论

1. **RECOMMENDED：保留 Utility 作为任务效果/代价的可解释比较形式，把“逐项选最高分”增强为有界联合候选搜索。** HTN、Utility、资源分配不在同一层。Horizon 的生产架构把 HTN 分解与 Utility 角色分配结合，但其角色分配示例仍是优先级顺序贪心。不能因采用 HTN 就宣称解决了正面牵制与侧击的互补收益、同时到达或预备队机会成本。[H1]
2. **RECOMMENDED：用少量带依赖与时间窗的组合，显式表达一个任务何时能够支撑另一个任务。** 普通一对一分配的可加目标不包括组合互补。经典 MRTA 原文还明确排除了任务排序依赖。因此匈牙利算法可作独立任务分配的对照/子程序，不能直接当作完整 Commander。[M1]
3. **RECOMMENDED：当前计划是同口径候选；继续的优势来自剩余到达成本、职责连续和不必要切换代价，硬失效不被滞回锁住。** Killzone 2 的 continue branch 是这一产品机制的直接先例；其具体 5 Hz 频率不是 CB2 预算建议。[K1]
4. **延期真实前滚搜索。** PGS 与 CMAB/MCTS 的优势依赖可廉价反复运行的状态转移/战斗评价。CB2 没有经验证的同等模型，本次应借有限候选和可中断改进，不借用其 rollout 分数、收敛结论或性能结果。单坐标 PGS 又可能漏掉必须一起替换的牵制—突击组合。[P1,C1]
5. **RECOMMENDED：有限反应情景只检查计划脆弱性，不伪装胜率预测。** 当前敌方部署全部合法可见，未来是否迎击、转向、撤后、援护仍未知。先保留少数与目标相关的反应及 ETA 区间，检查窗口/职责是否仍可成立；无数据时不用“30% 反击”等概率。
6. **RECOMMENDED：主动试探必须有边界、退出和复发抑制。** RBM 的 flank sortie 展示了“不能只用中心点追击距离、还要考虑散乱、时限、回收与冷却”的同生态失败模式。其用途是保护翼侧的反应性出击，不是已验证的诱敌信息价值算法。[R1]

### R1 — RBM：同生态可执行机制，不能跨用途当任务预测器

原始来源：[repo](https://github.com/Fellow93/RealisticBattleProject)、[AI 手册](https://fellow93.github.io/RealisticBattleProject/features/ai/)。以下代码链接固定 commit。

**原机制与证据。** [Lifecycle.cs L22–39、L55–119](https://github.com/Fellow93/RealisticBattleProject/blob/7f9069b6e111c7ce124f07545f0edef8202042bf/RealisticBattleAiModule/AiModule/Tactics/Lifecycle.cs#L22) 注册 Formation 行为、按攻防/文化安装战术；[FlankBehaviors.cs L24–63、L283–348](https://github.com/Fellow93/RealisticBattleProject/blob/7f9069b6e111c7ce124f07545f0edef8202042bf/RealisticBattleAiModule/AiModule/Behaviors/FlankBehaviors.cs#L24) 限定出击、回收与冷却，并检查骑兵散离比例；[CavalryCharge.cs L320–394](https://github.com/Fellow93/RealisticBattleProject/blob/7f9069b6e111c7ce124f07545f0edef8202042bf/RealisticBattleAiModule/AiModule/Behaviors/Custom/RBMBehaviorCavalryCharge.cs#L320) 按距离、类型、相对强度、朝向逐目标打分。实读代码说明这些是具体行为机制，不能证明整体效果更好。

**CB2 缺口 → 可迁移。** 将“去冲目标”补为具有职责对象、允许距离/时间、召回条件、再入冷却的局部执行契约；可用朝向与有限邻接敌队形成候选。**不可迁移：** 不复制文化战术菜单作为完整战术空间；不把局部目标分数提升为全军收益；不引入逐 Agent 阻挡/武器/Frontline 修改。散离检查依赖 Agent 遍历，CB2 应优先消费已有聚合观测或低频采样，不能隐藏其成本。

**代价、最小验证、采用。** Formation 上持有小型阶段/冷却数据即可，但必须并入既有任务执行阶段而非第二个任务生命周期。用“目标离开、半队散离但中心仍近、回收途中新威胁”三类受控回放检查退出行为；实机核验聚合指标和命令可控性。**采用机制，阈值重新测；源码不复制。**

**用途隔离。** [POWER_COMPUTATION.md §0–1](https://github.com/Fellow93/RealisticBattleProject/blob/7f9069b6e111c7ce124f07545f0edef8202042bf/RBMCampaign/POWER_COMPUTATION.md) 明确分开战略 Party power 和自动结算 blow power，模型/尺度不同。装备、技能可提示能力画像要超越 tier；这些 Campaign 标量不能直接证明野战某次牵制、侧击或射击任务的损失与效果。

**代码/手册差异。** 同提交 `manual/docs/features/ai.md` 的骑兵说明仍写先选步兵再弓兵，而上述 `AcquireTarget` 实际遍历所有合格敌编队并比较评分，其注释说明这是对旧选择的修正。对这一点采用代码限定当前行为；手册仅作设计/功能入口，不能按手册措辞推断未核源码。

**许可与版本。** 对固定提交的完整 `git ls-tree -r --name-only HEAD` 检索 LICENSE/COPYING/COPYRIGHT 无命中，已读取 AI Readme，未找到明确复用授权。公开可读不等于授权复制；如要复用代码须另核授权，本次独立写算法。RBM 工程显式 `.NET Framework 4.7.2` / C# 7.2，但引用本地引擎 DLL，源码本身不能证明匹配 CB2 目标 `v1.4.8.119303`。

### H1 — Horizon：Utility 与 HTN 是互补层；角色分配是有竞争力简单基线

原始来源：[官方页面](https://www.guerrilla-games.com/read/the-ai-of-horizon-zero-dawn)、[官方 PDF](https://www.guerrilla-games.com/media/News/Files/The-AI-of-Horizon-Zero-Dawn.pdf)。

**原机制与证据。** p15 同一决策核心服务组与个体；p22–25 的角色请求有标识、上下文、优先级、人数上限，依次查候选 utility 并分配，组可调节后续请求优先级；p26 的攻击选择也用 Utility 接入 HTN 前提。该页目标包括控制战斗节奏和玩家体验，并非无条件胜率最大化。

**CB2 缺口 → 可迁移。** 把角色的需求、候选适配和实际资源分配分开；先做有约束的贪心对照。**不可迁移：** 一次攻击者上限、玩家公平性、机器群的具体组层次不能直接成为大型战场限制。

**代价 → 最小验证 → 判断。** 不需要先写 HTN 语言/编译器；每任务—编队边给出能力、代价、理由，评估同候选集贪心与小组合枚举在职责竞争下是否不同。若每场最多独立的一对一职责且差异很小，保留贪心更合算。**采用作为强简单基线与接口分层；HTN 全面替换延期。** 没有源码可供本次复用。

### M1 — MRTA：匹配问题的边界必须显式

原始来源：[作者入口](https://www.robotics.stanford.edu/~gerkey/research/mrta.html)、[原论文大学镜像](https://www2.cs.sfu.ca/~vaughan/teaching/415/papers/gerkey-mrta.pdf)。

**原机制与证据。** §3 将适配视为预期执行质量减资源代价，并强调漏入全局评价的外部影响；§5.1 的独立一队一任务可转最优匹配。§1.1 明确该分析不包含任务排序约束。

**CB2 缺口 → 可迁移。** 分离“某队能做/做得好”与“联合分配后全军得到什么”；小规模独立问题可用枚举最优作参照。**不可迁移：** 对含牵制依赖、支援窗口的全问题不能套用匹配的最优性；高损失牵制的价值必须依联合结果/维持职责评估。

**代价 → 最小验证 → 判断。** 一个任务效用表不够，需至少显式依赖边或组合效果项。用一支机动队竞争进攻/保护/预备职责、侧击需另一队牵制的反例检验单边贪心。**采用问题界定；不新增分布式拍卖/通信框架。** 无算法代码复用。

### P1 — Portfolio Greedy Search：借候选收缩，不能借战斗模型的可信度

原始来源：[作者 PDF](https://davechurchill.ca/publications/pdf/combat13.pdf)、[共同作者 PDF](https://skatgame.net/mburo/ps/combat13.pdf)。Churchill & Buro，2013。

**原机制与证据。** §V 用有限脚本给每单位生成动作，逐单位改良脚本分配，可对敌方策略再回应；每次改良借助 playout 评价。§II 的 SparCraft 明确是简化 StarCraft 战斗模型，遗漏或简化具体游戏性质。

**CB2 缺口 → 可迁移。** 以有限任务生成器压缩搜索，始终保留当前可行解并按预算改良。**不可迁移：** 缺少可信模拟器时，不能把对抽象模型 rollout 当作未来战损；论文的时限/兵力成绩不外推 Bannerlord。

**代价 → 最小验证 → 判断。** 对 F 个编队、P 个候选行为、I 轮、R 次响应，评价次数约 O((R+1)IFP)，另乘模型评价成本。单坐标改良可陷入“只有同时换两队才获益”的局部最优；用两队互补反例比较单坐标、双变更、穷举。**首版采用有界可中断思想，搜索联合小组合；前滚与 PGS 主求解器延期。** 本次未复用 SparCraft 源码，因此未以其许可证授权任何复制。

### C1 — CMAB：联合组合要评价，局部均值不是协同真相

原始来源：[作者论文全文](https://arxiv.org/html/1710.04805)、[PDF](https://arxiv.org/pdf/1710.04805)。Ontañón，JAIR 2017，arXiv v1 2017-10-13。

**原机制与证据。** §3–4 把各单位动作组成联合 macro-arm，保留合法性函数；局部 bandit 产生探索组合，全局 bandit 记忆已采样组合。局部可加近似用于探索，并非直接证明联合收益可加；§2、§7–8 仍需要 μRTS 的转移与 rollout。

**CB2 缺口 → 可迁移。** “先构造合法联合行动，再整体比较”与独立打分不同。**不可迁移：** 首版不存在可采样大量同状态战斗回报的接口；不得把真实战场的每次试探等同于无成本模拟采样。

**代价 → 最小验证 → 判断。** 组合数巨大而时间窗又短时，采样可能漏掉互补组合；先在小问题用穷举测候选覆盖/组合损失，再决定是否需要抽样。**不采用 bandit/训练模块；保留为后续有可信模型时的竞争路线。** arXiv 页面为 perpetual non-exclusive distribution license，不是代码许可证；未下载/复用作者 Java 实现。

### T1 — 时间约束：先解决所需小子集，不直接接通用调度器

来源：[作者出版记录](https://ics.uci.edu/~dechter/publications.html)、[1991 原论文扫描 PDF](https://ics.uci.edu/~dechter/publications/r10.pdf)。阅读边界见检索表。

原文 §3 将 `a ≤ t_j − t_i ≤ b` 转为差分约束图，以负环判不一致，Floyd–Warshall 求闭包为 O(n³)。可借的表示为事件时间差区间，如 `hold_start ≤ strike_start`、`strike_end ≤ hold_end`。CB2 首版依赖 DAG 加少量覆盖窗口即可检查；**时间网络可满足**不代表敌方允许其兑现，也不等于含不可控时长的动态可控性。完整 STN/STNU、资源析取调度和通用规划库暂不引入。若首版出现跨多个任务的连锁时间修补再升级；最小验证是把单独可行但联合无交集的窗口拒绝，而非只比较单个 ETA。此为设计建议，论文定理不自动证明本次原型。

## 4. 在同等约束下比较真正的方案

共同输入：当前合法全信息 Formation 快照、相同有限任务候选、相同能力/ETA区间、相同权限与执行接口。共同输出：有资源所有权与职责覆盖的下一计划；共同保留当地合法安全路径。下列复杂度只计纯 Core，任何引擎查询另计。

记 F=可用编队数，C=通过权限/能力粗筛后的任务实例数，R=每实例引用的编队/目标/职责数上限，E=依赖边数，S=有限反应情景数，L=允许同时改动的实例数上限，B=搜索扩展上限。

| 方案 | 表示与过程 | 能力/失败 | 首版成本与预算耗尽 | 判断 |
|---|---|---|---|---|
| 守卫后的 Utility 贪心 | 对实例计算任务效果—代价；必须职责优先，按边价值排序，互斥检查后入选 | 支持独立任务、基本覆盖；局部互补与机会成本会漏算；排序对资源竞争敏感 | 排序 O(C log C)，接受筛查 O(CR+E)；截断返回已覆盖职责的可行解 | 必须保留的竞争基线，绝非“全军冲锋”弱对照 |
| 独立任务匹配 | F×任务槽的代价矩阵；一队一槽最优匹配 | 能解决单独任务的资源竞争；不自然表达 AND 依赖、联合收益和覆盖窗口 | 标准方阵匹配 O(N³)；组合槽展开后变成不同问题 | 仅在职责可加/独立时采用，首版不另加库 |
| **有界小组合搜索** | 当前计划为种子；由关系生成候选与支持候选，扩展至多 L 个变更；检查互斥、DAG、窗口和职责；按 S 个反应情景比较 | 可明确表达两三队协同；仍可能因候选/变更上限漏解；模型差则更精确地优化错误目标 | 未截断组合上限 Σ(k=0..L) choose(C,k)，每组合约 O(kR+E+S·kR)；实际 B 计数封顶，保留完整可行 incumbent | **主推荐**；先小尺度枚举作抽象参照，再必要时剪枝 |
| 手工 HTN 分解加贪心角色分配 | 方法分解给定战术，再分配角色；可用 continue 分支 | 可编排阶段和恢复；新战术受方法库覆盖限制；仍需资源/效果评估 | 方法分支与回溯可指数增长，必须深度/展开上限；C#纯核心实现或作者工具均有成本 | 保留既有任务/执行结构；不以重写 HTN 为首批工作 |
| PGS/滚动对抗前滚 | 为每队选脚本，反复前滚自己/对手；局部改良 | 可表达持续后果，但依赖转移/终局评价；单变更陷阱、对手模型错误 | 评价次数×模拟成本，远高于静态窗口；可中断但返回结果未必可信 | 当前延期；有实机标定数据后用作挑战者 |

**有界小组合不是完整通用部分序规划器。** 它只让现有任务的开始/结束、支撑关系和有限变更一起接受检查。L、C、B、S 是可配置的预算/能力参数，不能按场景 ID 写死答案；上限变化应在报告中显示机会覆盖和拒绝原因。先考虑双方不同更新次序，防止在一个固定同步顺序上得出优势。

## 5. 可直接用于原型/开发的机制建议（研究推论）

### 5.1 候选和组合必须来自状态关系

- 对每个可用编队，基于距离、相对朝向、目标角色、已有接触/射界/通道/保护职责产生有限的 `Maintain / MovePressure / Engage / Support / Cover / Recover` 参数化任务；这里列的是语义，不要求改名既有任务。
- “敌弓兵暴露”仅产生机会种子。查其邻近支援队的最早影响时间、我方到达区间、展开/脱离需求；需要牵制时追加能执行的支持候选，不能先写入唯一正确侧击模板。
- 对相同资源集合和目标，明显被支配的候选可删；未知能力、无射界、路径未验证不能统一算成可行。未知可以保留为风险更高、动作较小且可退出的候选，关键依赖未知则不能签发硬承诺。
- 当前计划须以**剩余成本**重新估值，不能用开始时总成本对比新计划的未来成本；当前计划已付成本是沉没成本，但撤出/重组和职责交接是新的成本。

### 5.2 三种不同的关系不可混为一个“支援加分”

1. **硬前提：** 所依赖的支撑职责已被分配且其执行条件有效；若缺失，不允许突击出发。
2. **时间覆盖：** 某任务需要的 `[start,end]` 必须被支持方的可维持区间覆盖；不只是两者都已抵达。ETA 区间与损失上限均为估计，不保证真实兑现。
3. **条件效果：** 有支持时侧击暴露风险下降/窗口变长是模型假设，必须与事实字段分开记录；不重复叠加击杀、威胁消除、目标收益三份价值。

一次 Formation 在同一时间段只有一份主动作承诺，但可承担与主动作兼容的职责；兼容性需显式表述，不能让“支援”标签绕过资源互斥。增援未真正进入可控 Formation 前不算即时资源。

### 5.3 情景、不确定性与有限主动性

首版对每个机会至多选少量有区分力反应：敌人维持、支援队提前迎击、目标后撤/朝向改变；没有可靠先验时不做概率加权。联合效应可用区间或序关系，优先检查硬职责及不利后果是否仍可接受。若一个候选在所有保留情景都不差且某情景更好，形成稳健支配；没有支配时必须记录风险偏好/职责优先级，不能说它客观唯一最优。完全 maximin 也可能过度消极，应把风险限制与正常效用比较分开。

当双方维持且没有已确认机会时，可在**允许职责风险**内生成有限 `MovePressure`：沿已验证通道小步前移或换射角，设最大暴露、最晚退出和回收点；观察敌方是否转向、支援覆盖是否变化、射界是否实际打开。敌不移动是有效结果，不能据此继续升级至无界追击；敌反击时先执行本地合法退出，再上报相关机会失效。对相同“目标+动作区域+反应”保留短期失败记忆直到新证据改变条件，防止无效重复。此机制是本研究提出的可证伪方案，**没有外部材料或本次实验能证明其提高真实战斗胜率**。

### 5.4 搜索与稳定性的最小可证伪点

- 若去掉依赖/覆盖时间窗后仍能在所有不同 ETA 用例中作同样选择，说明情景未区分主攻机制，需重设计输入。
- 若去掉切换代价/继续分支仍没有增加无效换令，不能宣传稳定性收益；硬失效后保持不动则直接否定当前滞回设计。
- 对 C 小的场景枚举所有可行组合，报告有界解距该**抽象问题参照解**的差距；不称全游戏最优。
- 在互补性消失、ETA 不确定性放大、支持效果趋零时，组合搜索应能退回简单方案。若只在一个任意权重附近优胜，降低推荐强度。
- 无实机前最容易推翻主推荐的实验：对受控 Mission 同时记录下令→动作生效→接触/射击→职责作用，若 ETA 区间与支撑判据频繁失配，先改善测量和窗口模型，不继续加搜索深度。

## 6. 证据等级与交付边界

本文件提供的是原始来源核读与机制推论；源码静态事实不自动构成第一层逻辑性质验证。可由主原型验证的资源不冲突、窗口覆盖、预算截断/回退属第一层；合成输入下较基线改良属第二层；真实 Bannerlord 的战损、胜率、Frame budget、Native/RBM 共存与控制权属于第三层，均待实机。

**不确定性优先级：** 合法命令是否准确生效与能否退出 → ETA/射界/职责效果观测 → 联合时间窗是否可预测 → 再考虑更深搜索或学习。复杂算法优于简单方案的必要条件是它得到的关键差异信息真实且能改变行动。

本次只保存外部来源证据，不修改正式产品原则或 P3 合同。所有采用项是 `RECOMMENDED`；引擎 API/时序/聚合指标可用性为 `NEEDS_ENGINE_EVIDENCE`。若需要改变允许牺牲职责、风险预算或全信息原则，则另标 `NEEDS_OWNER_DECISION`，不能靠算法默认值改写。
