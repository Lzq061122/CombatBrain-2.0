## 1. 产品定位、原则和首版硬范围

1. **胜利与有效指挥优先**：目标是更强的真实战术表现，而非刻意制造多样性、更多战术脚本、更多指令或拟人性表演。避免无谓损失，但允许为整体胜利付出必要局部牺牲；不设胜负与伤亡固定 50/50 目标。
2. **仅 Commander / Formation 层**：可编排、评价、重组、调动 Formation；原生 Agent 个体攻击、格挡、寻敌、个人士气溃逃和底层移动不改动。某种预期表现若需深度接管 Agent 才能实现，应缩减承诺或后置。
3. **首个可发布版本必须同时包含敌方 AI 增强和玩家 F6 托管**，两侧分别通过，不可只交付一侧。
4. **必须支持正常战役野战，包含多个领主队伍参战的军团野战**；CustomBattle 作为开发、调试与对照环境。首版专注标准野战，不将攻城、特殊战斗或多人模式误纳入已确认支持范围。
5. **玩家有效直接命令优先**。部分编队手动、部分 F6 托管可以并存；手动编队仅作态势与协同约束，不应被写令或私自重组。玩家全军撤退由玩家决定；敌方 Commander 不把全军撤退当作常规自动战术。局部战术撤回与整军退出必须分开。
6. **首版必须实际具备战术驱动的 Formation 拆分、合并和重组**，并提供 MCM 开关。默认保留原有编队稳定性；仅收益明显优于重组代价且拥有合法指挥权限时增量优化。尊重玩家/初始部署；激烈接战期间原则上避免大规模重组，可在安全条件下局部抽调。重组失败维持原结构；玩家手动接管立即生效、保留当前编组、取消未完成或待执行的 CB 重组及冲突命令。MCM 关闭时不能偷偷执行重组。
7. **援军系统不接管**：不修改原版援军出现时间、数量、组成或顺序；根据已经入场且有权控制的可用兵力规划，对新入场兵力增量纳入。未入场援军信息最多是可靠性有限的辅助信息，不能当作已经可调遣的部队。
8. **正常士气可沿用原版**：Commander 应能感知/响应溃逃和失序；重做 Agent 士气系统不是首版必要条件，“死战不退”实验不代替正常士气验收。
9. **信息公平且效率有界**：可观察完整战场态势，但不得读取敌方/玩家尚未执行的内部指令、隐藏意图或未来事实；不以人为延迟、故意失误和额外信息屏蔽制造低 Tactics 指挥官差异。
10. **兼容策略分层**：CombatBrain 保持独立战场 AI；RBM AI 等竞用 Tactic/FormationAI/Order 控制面的 Mod 首版不要求深度共存（优先允许关闭 RBM AI）；RBM Combat 的配合和独立画像按实际运行模式验证。Limitless 万人同屏纳入正式兼容目标，若实际兼容成本可控并通过专项测试，争取首版同发；不作为正常规模版发布的无条件阻断项。其他兵种 Mod 的专项兼容暂缓。

## 3. 任务契约与评价闭环

**两轴验收**：执行状态（EXECUTING / AT_RISK / BLOCKED / COMPLETED / FAILED 等候选状态）与行为合规（授权内 / 可能越权 / 证据不足）。VIOLATION 是另一维，不应与 FAILED 混同；枚举和阈值未签收。

每项任务至少指定：任务类型及目标对象/区域、实际战术效果、权限与允许机动范围、主要约束和重要性、完成条件、受阻/失败条件、终止/撤销与反馈责任、依赖的友军行动及有效期。Commander 上层可持有“制造右翼突破”等抽象目标，但 Formation 只接受具备可观察语义的任务，而不接受无法验收的开放式描述。

**具体反例：**
- 迟滞：步兵依令阻击但最终被击溃，是任务失败而非违令；未经授权追杀散兵、导致防区丢失，则可能是违令。
- 牵制：接敌不是成功；必须检查敌方是否真的被限定在关键区域、目标是否仍有自由转向能力。敌军行动的原因通常不可直接获知，应报告已观察效果，而非臆测“敌军被骗”。
- 包抄：骑兵到位不等于具备侧击条件；敌军拦截能力、我方牵制持续性、到达时间及机会窗口均需复评。
- 掩护：保护友军不是只到达目标点，需在威胁出现与消退时保持有效拦截能力，且不得擅自追击而脱离保护范围。
- 紧急避险：已明确可用的紧急权限不算违令；敌军冲散造成的位置偏离在无意图证据时标为受阻/不确定，不能武断定罪。

**典型协同结构**：Commander 的“右翼局部优势”可分配步兵 A 牵制中央、骑兵 B 掩护包抄方向、骑兵 C 机动侧击。C 的阶段推进取决于 A/B 的实际履职和敌军可观察的反制能力。失败时优先局部重规划，保留仍有价值的部署。

**候选任务家族 [尚未签收]**：区域保持/拒止、要点夺取、迟滞/牵制、友军保护/截击、正面推进/突破、侧翼机动/侧击、远程支援/袭扰、追击/扩大战果、组织脱离/重新集结/待命支援。必须逐个定义可执行输入与合规/结果验收；不因名字多就声称超越 RBM。

## 4. 能力画像、文化与 RBM 的可借鉴边界

**离线基础画像**：对选定游戏版本中的原版兵种，收集可能装备组、武器、技能、护甲、盾牌、坐骑及相关差异；研发环境离线分析并进行对抗测试校准；记录数据与生成器版本、战斗模型和配置。禁止直接用 Tier 或任意人为 0—100 主观评分当“强度”。画像既描述多维能力（射程、射速/弹药、远近攻防、抗远程、反骑兵、机动、阵型适配），也描述面对不同敌人的**相对效能**；维度、估计误差和校准样本待确认。

**战场动态聚合**：Formation 依实际成员兵种数量、存活、可用弹药、骑乘状态、位置、地形、敌军对抗关系得到当前可执行能力。稳定数据可缓存，动态数据低成本更新；不知道属性不等于属性为零，低置信度下应减小高风险特殊任务的自信程度。混编中不得取主文化代替组成。万人同屏的性能负担可能主要来自 Agent 采样和阵型几何，而不只是 Formation 数量。

**文化**：以装备、技能、数量、地形和实际敌方构成决定可行战术；多个方案收益相近时文化可以做次级偏好。不同文化弓兵因射程、防护、射速/弹药、近战能力等差异产生不同安全距离、掩护需求和任务选择，而非硬编码“巴旦尼亚必定两翼弓兵”。

**RBM 已核查参考点**（基于 Fellow93/RealisticBattleProject 公开源码及手册，需以具体版本继续复核）：
- RealisticBattleAiModule/AiModule/Tactics/Lifecycle.cs：依领军者文化选择可用战术候选；这**不是**从装备自动生成文化战术。
- RealisticBattleAiModule/AiModule/Tactics/Custom/RBMTacticEmbolon.cs：用骑兵比例、等级和马具护甲作重骑兵战术适用性条件。
- RealisticBattleAiModule/AiModule/Tactics/FormationCounts.cs：远程武器及弹药影响编队分类。
- RealisticBattleAiModule/Utilities/Utilities.Formations.cs：持盾/冲击武器占比影响阵型。
- RealisticBattleAiModule/AiModule/Tactics/Custom/RBMTacticAttackSplitInfantry.cs 与 RBMTacticAttackSplitSkirmishers.cs：按武器和角色强度等条件尝试重新分组。
- RBMCampaign/STRATEGIC_POWER.md：装备感知的战略部队战力评价**不是**可直接当作野战 Commander 的多维任务画像。

**可借鉴但不照搬**：RBM 的持续性弓兵避险、骑兵冲锋—再集结、散兵前出—脱离、盾/反骑兵队形、交战状态感知、AI 日志与玩家指令边界可以成为我们的战术执行参考。**不**把 RBM 单兵 AI、Campaign 战力公式或其文化战术模板原样等同于 CombatBrain 的统一规划器；RBM AI 与 CB 在同一指令层存在潜在抢令，必须按 Mod 组合验证并明确禁用/退出路径。

## 6. 必须压力测试的隐含假设

- **“动态编队只是重组列表”**：真实引擎可控槽位、接战解列、AI/玩家交接、控制权变化可能导致坏状态；不能以 CustomBattle 小队成功外推军团。
- **“多领主等于多个可独立命令的 Team”**：领主归属、军团实际指挥权可能不按直觉映射；需要实测源 API 和所有权切换。
- **“画像完整就知道胜率”**：静态能力并非条件胜率，RBM Combat 配置和实际地形导致估计失配；需要基线及样本误差。
- **“低频 Commander 能抓所有机会”**：短窗口、机动时间和敌方应对使临时机会不可利用；应可明确选择忽略机会。
- **“Formation 都各自聪明就会获胜”**：局部自保破坏牵制或保护，必须把职责依赖和承诺显式纳入。
- **“博弈越深越聪明”**：分支爆炸、模型误差与计划反复切换可能反降战斗表现；有限前瞻和有界开销。
- **“RBM 经验可直接移植”**：它同时涉及 AI 和 Agent 层，且部分战力来自 Campaign 模块；职责范围与行为替换不可偷换。
- **“万人只把人数乘以五”**：阵型宽度/路径/地形可行性、Agent 采样、原生槽位和动作反馈可能成为新瓶颈。
- **“日志里命令已发就是成功”**：必须隔离 CB 发令、原生行为、最终战果及士气/Combat 数值模型影响。
- **“暂缓兼容就不必降级”**：即使没有兵种 Mod，读数暂缺、变动装备和部分数据错误也不能拖垮全军控制。
- **“MCM 关闭重组后依旧自动恢复初始队形”**：用户确认的是停止后续重组与保持当前合法状态，并没有授权在玩家接管时自动撤销已经发生的编组。
- **“已有 P0—P2 限定通过意味着 P3 或 F6/军团已完成”**：不成立，旧合同有严格边界。

## 7. 评价分层、发布判据与后续动作

| 证据层 | 必须检验 | 不可作为替代 |
|---|---|---|
| E1 执行/权限 | 有权写令、命令实际影响行为、停发/撤销/交还真实生效 | 仅记录发令 API 调用 |
| E2 任务履行 | 持续保护/牵制/调动、允许中断、失败、真实越权与不确定 | 单纯接敌、到达某位置 |
| E3 局部战术效果 | 敌军被限制、掩护有效、侧击机会出现/消失、部署可持续 | 单纯击杀数或计划文本 |
| E4 整场产品收益 | 同条件下敌军制造威胁，F6 更有用且尊重玩家，有意义损失控制 | 挑选孤例，或 RBM Combat/士气变化 |

**首版通过必须分别证明**：敌方 AI、F6、战役及多领主野战、合法重组/MCM、正常士气边界及已签收的最小任务闭环；未确定的最低多阶段能力、样本/胜率/战损阈值需要在最终澄清中决定，不能由本稿发明数值。

**分开标记兼容结果**：普通规模原版野战（必要）；RBM Combat 模式画像与运行配合（模型设计已确认，实际覆盖需按支持矩阵裁决）；Limitless 规模（条件式首发）；RBM AI 并行/其他兵种 Mod（非首发必要）。不能用“结构已支持”写成“已兼容”。

**阶段事实边界**：Roadmap P0/P1/P2 的历史限定验收照旧；P3 是否通过仅由当前相关证据决定，不根据本文时间戳推断最新状态。执行任务按当前 prompts/registry.json 为准；本稿不修改任务登记或进入实现。

**结束条件**：U01—U11 的首版关键产品取舍无悬空冲突；工程未知项有实测或明确接受的风险/回退；验证方法与门槛预先登记；由用户签收后再修订正式 Charter / Roadmap。后续讨论一次只推进一个核心问题，并持续维护决策溯源。

## 8. 这次研究稿相较 v0.4 的查漏补缺

1. **补为硬要求**：动态 Formation 拆分、合并、重组首版交付 + MCM 开关，不再仅写“必要时可拆”。
2. **补上手动接管语义**：保留当前编组、取消等待中的重组及冲突命令，不得擅自重排玩家的队伍。
3. **补上接战安全**：激烈交战时禁止大规模频繁拆合，允许安全局部调整，失败则留原队。
4. **补上援军的明确边界**：只管理已入场的合法兵力，不改变原生援军生成。
5. **补上标准野战的范围**：不能从军团野战支持推导攻城/所有特殊场景支持。
6. **补上时间尺度误解**：Commander 低频规划不等于只在低频采样；Formation 有授权内局部反应。
7. **明确尚未签收的任务家族、数值和算法**：不能用候选设计冒充最终功能验收。
