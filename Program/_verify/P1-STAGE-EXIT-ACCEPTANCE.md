## 2. 最后一项整改裁定

`BattlePlan.NoteSubmission` 与 `ExecutionGate.SubmitCandidate` 固定首次投递锚点；重复投递不延长 10 s 获选窗口。`FeedbackTick` 每 tick 扫描获选到期，位于待写命令消费前。Host 获选入口、Host 写令门与 Core 写令门分别拒绝截止时及截止后才首次获选的普通任务。独立退出动作继续使用自身生命周期。

## 4. 交接统计更正与退出动作

P 场实际 `EXIT_STOP_QUEUED / DONE / NOT_APPLIED = 2 / 0 / 2`，不是 2/1/1；两个退出动作未获选，分别等待 1.006 s、1.001 s 后关闭。保留实际离散 tick 耗时，不写成严格小于 1.000 s。按脚本允许的未获选关闭分支登记。

N 场为 1/1/0：退出动作 10.210 入队、10.553 投递、11.029 获选、11.036 写出 StandYourGround，距入队 0.826 s；CBATH 11.090 独立读到该命令。退出生命周期修复有实际写出实例。

P 共 7 次候选、6 次获选、6 次写令。因此“每一条候选都在 0.5 s 内获选”不成立，应限定为本轮实际获选的候选；未获选退出候选另列。P strength_ratio 实际范围 0.929–0.948，N 为 0.919；不影响未跨越继续条件区间的结论。
