## 1. 目标与边界

### 1.1 一句话目标
让 CB2.0 从当前战场条件推出**一个整体计划**（打谁、为什么、谁去干），把任务分给**多支编队**分别执行，并**自己读取实际状态**看到命令生效或失效；判断、下发、观察全过程带时间戳，且不能表现为"想到就立刻全体响应"。

### 1.2 与 P0 的边界差

| 维度 | P0 现状 | P1 新增 |
|---|---|---|
| 决策 | 无决策，固定阶段机（A/B 两段）在固定时刻触发 | 由战场条件产生**目标 + 理由**；条件变了任务分配跟着变 |
| 规模 | 一次 1 支编队，且限 Infantry | **多支编队**服务同一目标；控制类别扩到 Infantry＋Ranged |
| 命令 | 只有 Stop | 三种任务语义：`Hold` / `Engage` / `Reposition` |
| 反馈 | 已记录实际后值 + 独立观测，但只服务于单点意图 | 接入**计划级反馈**：命令是否真的生效、计划依赖条件是否仍成立、条件失效时停止或转安全处置 |
| 时序 | 固定 15s/5s/6s 测试节奏 | 决策周期 + 计划最小稳定时间 + 非零首次指挥延迟 + 编队间延迟，四类时间分别记录 |

### 1.3 明确不做（非目标）
完整兵种角色库、复杂战果利用、主动试探、针对玩家的固定反制脚本、完整收益评估与重规划（留 P3）、Facing/Arrangement 命令域、预备队识别、`ChargeToTarget`、骑兵/骑射类别、全兵种×全命令矩阵、通用调度/配置框架。

### 1.4 关键帧（本阶段必须能看到的现象）
- **K1 组队时刻**：一次决策输出里有「1 个目标 + ≥2 支编队各自的任务」，每支编队的任务都能追到**同一次 BattleState + 同一个 Plan**。
- **K2 分头响应时刻**：至少两支编队的**实际命令写入时间**不相邻（可测量先后差），不是同一 tick 集体响应。
- **K3 生效时刻**：CB2 自己读到的实际状态 + CBATH 1 Hz 时间线都显示被指挥编队的 `movement_order` 真的变了；`Move(position)` 还要有实际目标位置。
- **K4 失效时刻**：Plan 预设的失效条件**真实变为不成立**，生产 Plan/任务因此停止或转安全处置——不靠原测试计时到期，也不是再写一条同样的命令。
- **K5 稳定时刻**：条件不变的时间窗内，计划不重算、不重发；时间线能证明没有逐 Tick 改主意。
- **K6 换条件时刻**（跨场次）：换一套关键条件配置重跑，得到**不同的任务分配**（不是同一套写令换 Plan 名字）。

## 2. 已取证的硬约束

1. **AI 队没有、也无法合法拿到 `OrderController`**（功能草案 §7.2 三重实证）。命令只能走 `Formation.SetMovementOrder` 或我方 `BehaviorComponent`。
2. **原生每 tick 重选最佳行为**（`FormationAI.FindBestBehavior`，`WeightFactor` 参与打分）。我方行为要被持续选中必须保持权重。→ 多编队 = 每支编队各挂一个我方行为实例。
3. **`IsAIControlled=false` 时我方 `TickOccasionally` 不会被调**，原生也不会替我们写令（`FormationAI.TickOccasionally` 的 `if (_formation.IsAIControlled)` 分支）。→ P0 的资格门必须继续生效。
4. **`Formation.SetMovementOrder`**：每次调用末尾**无条件 `SetTargetFormation(null)`**；对"实际相同"的命令走 `AreOrdersPracticallySame` 短路。→ 不能拿"又调了一次 setter"当生效证据；带目标编队的命令副作用大。
5. **`Formation.SetControlledByAI(false)`** 会调 `AI.ActiveBehavior.OnLostAIControl()`；`(true)` 分支会 `AI.Tick()` 并在行为仍是原实例时 `OnBehaviorActivated()` 再 `SetMovementOrder(AI.ActiveBehavior.CurrentOrder)`。→ 资格恢复时若我方行为仍 armed，原生会**替我们重推旧命令**，这正是"资格恢复不复活"的风险点。
6. **命令域验证状态**：Movement 域只验过 `Stop`（`Move→StandYourGround`）。`Charge` / `Move(WorldPosition)`，以及 Ranged 类别，属**未验证域**，必须在首次实际使用时验，且**不建完整 PoC 矩阵**。
7. **控制域现状**：`TargetSelector` 硬限 `IsPlayerTeam || IsPlayerControlled` → 排除；`!IsAiControlled` → 排除；非 Infantry → 排除。P1 扩到 Infantry＋Ranged。
8. **战斗构成现状**：当前 CBATH 入口每场产生同一套构成（实测两次完全一致：team0 24/25/25/25，team1 20/25/13/25/12）。team1 是这些场次被指挥的队，team0 是玩家队——**是事实记录，不是代码里的常量**。

## 3. 方案骨架

### 3.1 决策层（Core，纯逻辑、可单测）
- **BattleState**：一次评价消耗的**已标识**态势快照。每个字段注明来源（实读 / 派生 / 缓存 / 未知）。**不能用采样时间冒充缓存字段的实际刷新时间**（如 `QuerySystem` 的内部缓存）。
- **Assessment**：从 BattleState 得出主要优势 / 主要威胁 / 目标，不引入完整评分，不硬写加权和。
- **Plan**：目标 + 理由 + 承担任务的编队 + 继续条件 + 失效条件。**Plan 与 Order 分层**。
- **Task**：`Hold` / `Engage` / `Reposition` 三种之一 + 承担编队 + 对应命令 + 期望结果（含 `Reposition` 的目标位置）。

### 3.2 执行层（Host）
- 每支受命编队挂一个我方行为实例；行为按当前任务产出命令，经**执行前即时复核**后由主线程写入。
- `ThreadHandoff` 由单槽位**最小适配**为按编队键分流；P0 已验的锁、主线程登记、执行门顺序保留。
- **P0 固定驱动与 P1 自动指挥互斥**：同场只能有一个写令来源。

### 3.3 反馈层
- **生效判定**：CB2 自己读**真实 Formation 状态**（命令类型 + 对 `Move` 的实际目标位置 + 位置变化）作为在线反馈；CBATH 1 Hz 时间线只做独立核对。
- **失效判定**：按决策节奏继续评价、读反馈、查失效条件；继续条件不成立 → 停止或转安全处置。
- **未生效必须明确报告**，包括原生覆盖与未获选，不改成外部强写。

### 3.4 时序
- 明确区分并分别记录：**评价 / 计划变更 / 命令投递 / 实际执行**四类时间。
- 计划稳定期间仍按节奏评价与检查失效条件，只是不改计划。
- 资格丧失、Mission 结束等安全取消**不受稳定时间与指挥延迟约束**（立即生效）。

### 3.5 与 P0 的关系
- P0 既有通路保留可复现（回归）；P1 是新增模块，由独立开关控制，默认关闭。
- P0 的资格失效（`AiControlLost` / `PlayerEligibilityLost`）撤权逻辑在 P1 通路上同样必须成立。

## 4. 验收口径（形态；具体判据见脚本）

| Gate | 验收形态 | 观测来源 |
|---|---|---|
| 1 | 两场**实际构成不同**的战斗（远程优势成立 / 不成立）→ 不同的**任务分配或命令/位置**，不是同一套写令换名字；差异可追到条件差异 | 我方 Plan 记录 + CBATH 时间线 + 实际人数 |
| 2 | 每条自动命令可追到：同一 BattleState → Plan → Task → 发令原因；CB2 在线反馈 + CBATH 独立观测共同证明生效，或明确报未生效 | 我方日志（含 `snapshot_id→plan_id→task_id` 串联）+ CBATH 1 Hz 时间线 |
| 3 | 条件不变时计划连续（不逐 Tick 改主意）；失效条件出现时停止不合适动作；时间戳证明**不同编队不是同时响应** | 四类时间戳记录 + 时间线 |

**回归项**：主线程、玩家/AI 资格门、撤权、关闭不复活、Mission 清理在受影响的新通路上保持成立（尽量与 P1 两场合并取证，不要求无改动 P0 完整重跑）。
