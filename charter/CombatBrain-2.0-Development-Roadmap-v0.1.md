# CombatBrain 2.0 — 分阶段开发路线图 v0.2

> 状态：按项目负责人 2026-10-19 核心设计决策修订；MVP 最终环境和量化门槛待定。
>
> 上位目标：[Charter v0.3](Charter%20V0.2.md)。沿用原文件路径以保留既有引用，内容版本以标题为准。本路线图规定开发顺序、阶段范围与验收原则，不代表所列能力已经实现，也不自动替代当前任务的具体合同。
>
> 修订日期：2026-10-19。

## 1. 使用规则

1. 开发派单按 **Charter → 当前阶段 → 当前任务** 确定范围。阶段通过只表示本阶段目标已验证，不表示 Charter 最终目标已实现。
2. 每阶段必须交付可运行或可独立验证的结果。P0 是工程验证阶段，不宣称已形成 AI 决策闭环；P1 起才验证最小指挥闭环。
3. Exit Gate 必须有可复查的输入场景、运行构建身份、观测结果和判定记录。日志说明“CB 打算做什么”；战场状态与命令实际效果须由独立观测验证。证据不足记为 **未验证**，不能按通过处理。
4. P1 起保留已通过场景的回归，并至少增加与本阶段能力有关的对照或变化场景。在具备相关可测行为后，尽早引入少量实际玩家对抗和变化场景，提前发现战术收益缺口；P5–P6 承担正式的大范围泛化及体验验收。探索样本不替代正式阶段门。
5. 阶段范围列出的 CB 编号仅用于对照现有《功能拆解草案》，不是批准该草案的全部设计。其 PoC 使用 **FD-PoC P1～P11** 标识，与本路线图 **P0～P6**、CBATH 的 **Phase 1** 区分。PoC 结论以实际实验为准。
6. Charter 的范围约束、Commander/Formation 边界、玩家有效指令优先、信息公平、不故意犯错、Plan 与 Command 分离持续有效。允许完整战场视野，不读取玩家未执行的内部指令或隐藏意图；不把原版 Tactics 技能映射等同于新增养成系统，也不以低技能额外延迟或随机错误制造差异。
7. CBATH 是验证工具，不是 CB2 指挥能力的完成证据。CB2 加载、发令、职责、战术效果和整场收益分别判定；当前状态及限定范围见 §4。来源判别证据不足的命令保持“来源未判定”。
8. 不预设必须软注入或必须接管。关键职责所需可靠性由行为与证据决定；控制方案变化须明确受影响的权限、原生执行、安全及交还约定，不能把当前接入限制改写为产品必须接受的限制。
9. 依次区分计划生成、指令被接受及实际执行、Formation 履职、战术效果、整场结果。几何关系、写令回执、局部减员及检查器通过均不能跨层代替收益证明。没有证据记未验证；真实失败不能仅改日志或判据消除。
10. 保留既有阶段合同及其证据的历史作用域。新增产品要求不倒推既有验收已经覆盖，也不把已限定通过的阶段重新解释为完整产品通过。当前 P3 的具体合同衔接见 §4。

## 2. 阶段总览

| 阶段 | 本阶段回答的问题 | 主要交付 | 进入下一阶段的关键证据 |
|---|---|---|---|
| P0 工程基座与可验证指挥 | CB2.0 实际加载了吗？读数可靠吗？发出的 Formation 命令真的生效了吗？ | 构建身份、共享战场状态、独立观测、最小命令通路 | 同一运行中的构建身份、状态读数与命令效果可独立核对；控制权交接安全 |
| P1 最小指挥闭环 | 状态变化能否形成不同的全军计划，并执行、观察和处理基本失效？ | 最小评价、Plan、任务、执行、基本反馈、决策节奏与延迟 | 对照场景产生不同且可追溯的计划；实际行动有最小反馈闭环 |
| P2 多 Formation 协同 | 多支部队能否围绕同一目标执行任务且不相互抢令？ | 通用任务分配、跨 Formation 协同、命令冲突裁决 | 多 Formation 行为与同一 Plan 一致；竞争命令按权限处理 |
| P3 反馈、止损与重规划 | 能否可靠形成职责行动，并据真实结果继续、调整或止损？ | 执行可靠性、职责反馈、战果与代价评价、撤回和重规划 | 正、负变化触发实际行动调整，旧攻势是否停止有独立证据 |
| P4 主动权与战术博弈 | 有限战术能否灵活组合，并按对手真实反应调整？ | 战术候选与组合、有限预测、试探、技能预设接入 | 组合行动有效执行，有反应与无反应对照；能力差异来自评价与推演 |
| P5 泛化与稳健性 | 共享战术与指挥机制能否处理选定的真实野战环境？ | 场景矩阵、环境与控制适用范围、失效归因和必要补足 | 选定范围覆盖、回归与限制可复查，不靠逐场景新增独立系统 |
| P6 Charter 最终体验验收 | 友军是否更能帮助玩家获胜，敌军是否构成实际威胁？ | 预定实战方案、玩家对抗与托管对照、行为及收益审计 | 达到已确认范围和预定指标，指挥收益不与配置或规则变化混淆 |

## 3. 阶段定义

### P0 — 工程基座与可验证指挥

**目标**：先证明“正在运行的是 CB2.0、它读到的状态可信、Formation 命令能落地”。本阶段的测试命令可以由人工或固定测试驱动器触发，不代表 AI 已经会规划。

**允许范围**：

- 建立 CB2.0 独立构建及运行时身份；记录游戏版本、模块列表、构建标识与实际加载 DLL 的一致性，明确区分 CBATH、旧 CombatBrain 和 CB2.0。
- 建立可刷新的双方 Formation 共享状态，并以独立采样检查人数、兵种、位置、状态及刷新时效。旧版暴露过的敌我混淆、兵力重复计数、预备队误判必须纳入针对性检查。
- 建立独立于 CB 决策日志的战场与命令效果观测。CB 自身写令可精确记录；外部命令若缺乏足够证据，标为“来源未判定”，不得推断为某个原生子系统。
- 验证最小 Formation 命令通路、原生覆盖情况及控制权归还。优先用一项可观察的命令域证明通路；其他域分别记录“已验证／未验证／受阻”。
- 对接现有功能草案的 CB-001、CB-014 与 CB-002 的最小部分。执行 FD-PoC P1/P2；采用 Route A 时验证 FD-PoC P11。其他引擎签名或时序 PoC 按实际触及的命令域执行，不把未经验证的域算作可用。

**非目标**：作战计划、兵种战术、机会利用、胜负评分、完整的原生命令来源分类。

**Exit Gate**：

1. 一场真实 CustomBattle 的记录能把 **运行构建身份 → 双方 Formation 状态 → 测试命令 → 战场实际命令／行动变化** 串在同一场次和时间线上；独立观测与 CB 自身日志分开保存。
2. 至少一次测试命令被证明确实作用于目标 Formation；若被原生系统改写，观测能识别“命令未持续生效”，不能仅凭 CB 调用日志宣布成功。
3. 玩家接管、租约结束或战斗结束时，CB 不继续抢令；相关控制权边沿有实机证据。FD-PoC P1/P2 的结论及适用命令域已记录；若关键命令域无法安全控制，停止向依赖该域的 P1 方案推进并回到设计评估。
4. 战场状态的刷新、敌我归属和人数统计通过独立核对；未能判断的字段明确标记，不以空值或旧快照冒充当前事实。

### P1 — 最小指挥闭环

**目标**：用最少的状态、评价和任务语义，让 CB2.0 从战场条件形成一个可执行的整体计划，并观察执行结果。这里的“闭环”仅包括基本生效与失效反馈，不要求成熟的战果利用或重规划。

**允许范围**：

- 建立最小己方能力与敌方态势判断，形成当前主要优势、威胁和目标；Plan 记录目标、理由、承担任务的 Formation、继续及失效条件。Plan 与具体 Order 分层。
- 至少让多个 Formation 的任务服务于同一目标。P1 只使用验证最小闭环所必需的任务类型，不一次做满功能草案的七类任务。
- 对发出的命令观察是否生效，以及计划所依赖的关键条件是否仍成立；条件失效时至少能停止或转入安全处置。完整的收益评估与重新规划留给 P3。
- 从第一次实际自动指挥起实施决策节奏、计划最小稳定时间和非零指挥延迟，并记录时间戳；具体参数待实机标定。紧急止损若需越过稳定时间，须有明确触发条件。
- 对应功能草案 CB-003～CB-007、CB-012 的**最小必需语义**及 CB-008 的基础反馈，不代表这些功能在 P1 已完整交付。胜利优先，保全用于减少为胜利付出的不必要代价；不设固定 50/50 产品权重，不将局部减员当作整场胜率。

**非目标**：完整兵种角色库、复杂战果利用、主动试探、针对玩家的固定反制脚本。

**Exit Gate**：

1. 至少两种**关键条件不同**的战斗配置（如己方远程优势成立／不成立）产生可解释的不同目标或任务分配；改变输入后重新运行，不能仅改变 Plan 名称而保持同一套写令。
2. 每个自动命令均可追溯到同一个 BattleState 快照、Plan、Formation 任务与发令原因；独立观测证明命令实际生效或明确报告未生效。
3. 计划在条件未变时保持连续；当预设失效条件出现时能停止不合适的动作。时间记录证明没有逐 Tick 改主意，也没有全部 Formation 同时获得即时响应。

### P2 — 多 Formation 协同

**目标**：把 P1 的最小任务分配扩展为可处理多支部队和竞争命令的军队级指挥。

**允许范围**：

- 扩展通用任务语义与任务重新分配；任务不与固定兵种永久绑定。
- 对同一 Formation、同一命令域的竞争提案实行唯一裁决，并记录提案、拒绝或替换原因。执行层必须遵从当前 Plan 和任务权限；必要的安全接管属于显式规则。
- 验证主力、辅助和保护力量之间的协同，覆盖 Formation 损失或职责变化后的任务调整。
- 按任务区分中央约束与 Formation 自主执行，关键职责不能被原生局部决策轻易打断；不能借此机械坚持失去合理性的任务。几何关系是执行证据，掩护效果和整场收益另行评价。
- 对应功能草案 CB-007 和 CB-002 的协同与仲裁部分；P0 已建立的基本安全仲裁持续有效。

**非目标**：为步、弓、骑、骑射各建一套独立战略；把任务枚举数量当作协同成果。

**Exit Gate**：

1. 在至少三支己方 Formation 参与的场景中，能从同一 Plan 解释主力、辅助与保护任务，且独立观测支持这些任务确实被执行。
2. 注入相互冲突的命令提案后，最终生效命令符合事先定义的 Plan／任务权限；不存在多个模块交替覆盖同一命令的持续抢令。
3. 移除、削弱或改变一支关键 Formation 后，其他任务能更新或明确报告当前计划不可执行，而不继续执行失去前提的旧命令。

P2 已有验收仅证明原合同下有限三职责、空间关系、命令依赖、裁决和安全联动，不追认关键职责在所有原生干预下可靠，也不证明保护收益、战损下降或胜率提升。更强执行要求在 P3 相关工作中检验，不抹去原验收的限定结论。

### P3 — 反馈、止损与重规划

**目标**：优先建立可信的战术行动与反馈闭环，保证评价所依赖的行动和职责确实发生，再据结果继续、加大投入、改变方式、止损或重规划。

**允许范围**：

- 为行动定义可观测的预期效果与成本，并用相同维度记录实际结果；正、负反馈均进入共享评价。
- 对关键职责被原生干预、行动未持续、撤回未落地和反馈不足，先区分控制能力、调用接线、判据及缺证据问题，再据证据修复或明确最小控制契约差异；不反复靠站位、替补或重试补丁替代执行接入判断。
- 正反馈下判断是否扩大局部优势；在损失、威胁或前提变化时，比较继续交战、取消、掩护增援、局部撤回、集结再投入和改变计划的价值。分别定义实际采用动作的完成条件和反馈，不把取消计划当作已撤回。
- 胜利优先、保全服务于胜利。获胜机会接近时优先较低战损，可接受提高获胜机会所必需的局部牺牲。评价公式、量纲及阈值须按行为范围明确；当前局部战果指标不是整场胜率模型，既有等权公式不作为新的固定产品承诺。
- 重规划关联原因、时间及旧／新 Plan；阶段首先验证限定动作的实际闭环，不一次做满 MVP 的战术行为库、技能预设和完整撤回再投入能力。
- 对应功能草案 CB-008、CB-009、CB-012 的深化。

**非目标**：把每次兵力变化都触发为重规划；主动诱导对手犯错；完整技能预设；士气重构；未经具体契约论证直接切换生产控制方式。

**Exit Gate**：

1. 正反馈用例：实际行动与职责成立，出现可观测局部优势后，AI 基于该变化继续或追加合理任务，而非自动恢复静态；观测能关联行动、结果与决定。单有几何关系、原生战果或计划生成不算本门战术闭环成立。
2. 负反馈用例：原目标失去价值、敌方有效反制或己方损失显著增加后，AI 在既定决策节奏内调整或终止 Plan，并停止旧 Plan 不再适用的命令。需有独立实际订单或位移支持，分别记录退出尝试、落地、被拒绝或被后继接管，不能用停止发令替代停止旧攻势。
3. 对照运行中若只改变上述关键反馈，后续决策应随之改变；若未改变，必须能说明继续原计划的判据。正、负样例均以实际战场观测核对。

这些门检验限定行为，不直接证明整场胜率或伤亡改善，也不保证所有近战都能立即脱离。当前正式 P/N/C 合同、冻结参数与新产品原则的衔接见 §4；不能以本节文字替换检查器、自动降低门槛或宣布阶段通过。

### P4 — 主动权与战术博弈

**目标**：围绕有限战术行为的灵活组合发展主动权、有限预测和战术博弈；组合必须能够实际执行，并根据敌方真实反应持续调整。

**允许范围**：

- 在共享状态、评价、Plan、职责、执行和反馈中接入必要的预定义基础行动、战术知识与模板，组合推进、保护、机动、牵制等行为；不要求通用规划器或从零发明新战术。成熟原版或 Mod 设计可借鉴，具体代码及接口另验。
- 行动前考虑有限的对手可能反应，行动后按真实变化更新选择。高级预设允许更复杂组合，简单有效的行动仍可选；不以随机多样性或强制次优动作作为目标。
- 用可控对手先验证“施压 → 对手变化 → 我方识别”的可观测性；执行功能草案 FD-PoC P10。若原生 AI 不作出特定反应，记录适用条件，不把这一种对手行为当成 Charter 能力唯一实现路径。
- 验证玩家或受控对手的部署变化能进入判断，并改变行动价值与后续计划。对应功能草案 CB-010；CB-011 是否需要独立实现由实际变化检测缺口决定。
- 在同一基础系统中落实 MVP 所需的原版 Tactics 技能映射及指挥能力预设。任务前明确实际技能来源、区间和预设范围，这些尚未确定，不自行补入数值；不改成长和经验机制，不新增养成系统，不以低技能额外延迟或故意犯错区分能力。

**非目标**：依赖固定脚本阶段切换伪装“试探”；假设对手必然按预定方式回应；完整的高阶多阶段博弈、个人风格、交手记忆、大语言模型规划或通用战术发明。

**Exit Gate**：

1. 有反应与无反应两组对照中，AI 的后续选择取决于实际观测到的变化；改变反应方式后，后续目标或投入也相应改变。
2. 至少一次完整记录可追溯 **采取行动 → 对手反应 → 战场状态变化 → 价值重评 → 后续计划**，并能排除只按计时器进入下一脚本阶段。
3. 试探失败或代价过高时，P3 的止损机制仍能终止行动。若关键反应无法稳定观测，阶段不能按通过处理，须记录受限场景并重新审查该能力的实现路径。
4. 组合中的职责实际执行且有战术效果证据；只串联多个命令或增加模板数量不算成功。对已明确范围的技能预设，核对真实技能来源和生产选择结果，基础信息更新与调度一致，差异可追溯到评价、预测或可协调复杂度，不追认全部三层最终能力已完成。

### P5 — 泛化与稳健性

**目标**：检验已形成的指挥循环能否跨场景工作，并处理暴露出的通用能力缺口。

**允许范围**：

- 建立场景矩阵，覆盖兵力比、兵种组成、Formation 数量、攻防身份、玩家部署变化和战斗中结构变化；前阶段的验收场景持续回归。MVP 环境确认后，将相应的 CustomBattle／战役野战、玩家 F6／敌军指挥、士气条件和能力预设纳入矩阵，不把建议环境冒充全部已承诺或已支持。
- 对每个失败先定位状态表示、评价维度、计划候选、任务语义、执行或反馈中的缺口；有证据证明通用机制无法表达时，才按 Charter §21/§26 审查专用系统。
- 地形与站位能力仅在矩阵显示其确为决策缺口时进入实现；若使用功能草案 CB-013 的可行走性子项，先完成相应 FD-PoC P3。
- 核对所选环境的实际指挥权归属、玩家有效指令优先和全军撤退语义。尊重玩家的撤退决定；非玩家军队不把主动全军撤退作为常规战术，自定义 AI 不主动全军逃跑；Formation 局部撤回及原生士气溃逃另判。
- 先验证指挥系统能理解原版士气与溃逃，再按证据评估最小规则调整。士气损失、集体溃逃、Formation 重整可研究，但不深度接管 Agent 或新增个人士气状态机，也不把完整士气重构变成前序阶段前置。
- 在实际选定人数和环境下测量更新、评价与执行成本，依据明确的性能预算判定；不预设未经测试的规模或兼容承诺。

**非目标**：每出现一个失败场景就新增战术模块；无失败证据地做完功能草案中的全部候选项。

**Exit Gate**：

1. 场景矩阵、各配置的构建与运行条件、结果及失败归因可复查；至少覆盖上述每一类变化，允许一个场景同时覆盖多类。
2. 对导致目标能力失效的场景，要么以通用机制修复并通过回归，要么明确列为未解决限制；未解决限制不得被“其他场景通过”抵消。
3. 新增能力可说明其对应的 Charter 目标、通用机制缺口和回归证据，且未引入无关的情形专用规则链。
4. 对所选玩家托管或敌军场景核对真实权限和生命周期；正常士气条件下验证状态理解与相关动作。若另有士气调整，配置、对照及未验证边界独立记录，不能用“死战不退”覆盖正常条件。

### P6 — Charter 最终体验验收

**目标**：判断已明确交付范围内，友军能否更有效地帮助玩家获胜、降低不必要战损，敌军能否凭真实战术能力制造威胁、利用失误并在条件允许时击败玩家。

**允许范围**：

- 在正式实验前固定 MVP 环境、对手条件、玩家水平或测试方法、地图、兵力兵种装备、样本量、胜负、交换比、战损及关键战术指标，以及“通过”的判据。分别记录玩家亲自作战、F6 托管及 RTS Camera 等方式的适用范围；具体范围和胜率阈值未定，不自行添加产品承诺。判据尚未确定时，P6 保持未通过。
- 用相同配置对比 CB2.0、原版及可用的旧 CombatBrain；对照组用于解释差异，Charter 的玩家对抗目标仍须单独验收。
- 审计关键战斗决策与结果的关系：玩家能否辨认整体意图，AI 是否利用实际漏洞，职责是否产生战术效果及整场收益；区分指挥贡献与原生作战、个人操作、数值或配置差异，不将所有战果归给 CB2。
- 覆盖正常野战与正常士气条件，不能仅用特殊“死战不退”配置完成最终体验验收。若产品另采用经明确接受的士气规则，须单列规则变化的对照，保持指挥比较条件一致，不把士气收益当作指挥收益。
- 在失败场次定位属于 P0～P5 哪一环的缺口，修复后重复受影响的阶段门槛与 P6 对照，不用调参掩盖未闭合能力。

**非目标**：靠挑选单场胜利宣称完成；以“模块都存在”代替实战体验；为通过验收引入不公平优势。

**Exit Gate**：预先确定的实战判据达到要求，行为审计能够解释关键胜负因素，且不存在违反 Charter 核心约束的证据。结果不达标、样本不足或判据事后改变，均不得标记通过。
